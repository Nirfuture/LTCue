# 映像の同期復旧

## この資料について

この資料では、LTCに対して映像の復号が遅れたときに、ProgramPlaybackが現在の再生を続けながら別の位置を準備し、追従を回復する処理を説明します。復旧が始まる条件、準備中のジャンプ・入力喪失、画面の同期状態との関係を確認するときに参照してください。

ジャンプ時の採用条件は[現行仕様](../FINAL_SPEC.md#ジャンプ時の採用境界)、画面表示は[表示判定](../FINAL_SPEC.md#2-画面と初期状態)を参照してください。この資料では、ProgramPlaybackの復旧処理と診断情報を扱います。

## 全体の関係

本番のキュー再生（ProgramPlayback）で、LTCに対して復号済みの映像が遅れた場合の処理です。

入力LTCの受信状態と、映像の追従状態は別に扱います。入力がLOCKEDでも映像が遅れる場合があるため、表示するフレームのPTSと、そのキューに対するLTCの経過時間を比較します。

現在の復号と先読み・復旧用の復号で最大2本の資源枠を共有する。復旧用の準備ができるまでは現在の映像を使い、準備したフレームは対応する時刻になってから採用する。

## 通常の復旧

- 遅れが200msまたは動画の3フレーム分の大きい方を超え、復旧用の準備を開始できる場合に追従復旧を試みます。この値は復旧開始の閾値であり、画面の遅延表示の判定値ではありません。
- 現在の復号を維持しながら、LTCの現在位置より少し先を別の復号処理で準備します。
- 準備ができたフレームは、そのタイムコードに達してから採用します。
- 先読みする時間は、観測した初期準備時間を基に250ms～2秒の範囲で決めます。
- 復旧中は次キューの先読み用リソースを使い、現在の復号と合わせて同時に2つまでに抑えます。

## 失敗・取消・競合

- 復号が遅い間に同じ準備処理を何度も破棄し直すことはしません。復旧の試行開始は最短でも1秒間隔です。復旧用の準備に失敗した場合は、次の試行まで2秒待ちます。
- LTC入力が失われた場合は最後の映像を保持します。入力復帰やジャンプで世代が変わった場合は、古い復旧処理も破棄します。提示直前・観測値の採用時にも時計の世代と再生権限を確認し、待機中に届いた新しいLTCを優先します。
- 復号そのものが失敗した場合は、そのキューを同期対象から除外し、黒・無音で次の正常キューを待つ素材エラー処理へ伝えます。

ジャンプ時の準備位置、待機後の再評価、提示・観測値の採用条件は[現行仕様の採用境界](../FINAL_SPEC.md#ジャンプ時の採用境界)を基準とする。先読みの引継ぎにはキューIDだけでなく、素材版を含む定義の一致を要求する。

音声は現在LTCを独立して参照する。映像の復旧完了を音声開始の条件にはせず、映像の追従復旧だけを理由にWASAPI出力を再生成しない。

## 制約

物理ディスプレイ上の同期精度を保証するものではありません。処理能力が不足する場合はフレームの読み飛ばしや映像の保持が発生し、すべてのフレームを等速で表示することはできません。

## 表示判定との関係

画面の映像・音声の同期状態は[現行仕様の表示判定](../FINAL_SPEC.md#2-画面と初期状態)に従う。許容幅と継続時間を使う表示判定と、追従復旧の開始判定は目的が異なる。復旧中はタイミング表示を「再同期中」とする。

ProgramPlaybackのWarningは診断情報、Noticeはプレビューに必要な失敗通知として扱う。Warningに含まれる遅延文を、そのまま現在の画面表示仕様とはみなさない。

## 診断情報

ProgramObservationは次の診断情報を持ちます。

| 項目 | 内容 |
|---|---|
| LagSeconds | その時点で選んだ映像フレームの遅れ。入力喪失中や対象映像がない場合はnull |
| Recovering | 再同期用の復号を準備しているか |
| RecoveryAttempts | この配信で再同期の準備を開始した回数 |
| InputGeneration | LTCのジャンプ・復帰を識別する時計の世代 |
