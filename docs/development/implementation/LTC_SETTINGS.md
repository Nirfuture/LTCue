# LTC設定の適用と復旧

## この資料について

この資料では、LTC設定の変更を、各処理が時計・再生・入力機器・保存済み設定へどの順序で反映するかを説明します。設定変更後の採用時点や、入力開始・保存に失敗したときの復旧処理を確認するときに参照してください。

利用者から見た適用条件と反映時点は、[現行仕様](../FINAL_SPEC.md#8-設定保存障害)を参照してください。

## 全体の関係

MasterClockは時計の補間・閾値を、Coordinatorは再生位置の補正を、Monitorは入力ワーカーを管理します。MainWindowは変更する設定に応じて各処理を呼び出し、設定保存に成功した後で変更を確定します。

## 通常の適用

### 時計と補正

MasterClockは設定値と現在受信に使う補間時間を区別する。UpdatePolicyは設定値だけをロック内で更新する。Readは現在受信に採用済みの補間時間を使い、設定変更だけでは基準位置、世代、日跨ぎ、ERRORを変更しない。Acceptは以前の補間時間で受信途絶を判定し、新しい閾値でジャンプを判定した後、新しい補間時間を採用する。これにより、補間時間の延長でLOSTが復活しない。

Coordinatorは設定済みの補正とSyncRunに固定された補正を持つ。受信中に不一致があれば、旧実行の映像提示・観測・音声位置を採用しない。次のReconcileで旧実行を終了し、新しい補正の目標へ再同期する。LOST中は旧実行を保持し、新しい実受信が来た時に更新する。補正値の変更は既存の時計と再生系で処理する。

### 入力切替と設定の確定

MainWindowは画像・GPU資源・保存用一時ファイルを先に準備する。入力を切り替える場合はCoordinatorの所有権直列化を通して同期を解放し、黒・無音にする。手動素材は保持する。新入力の開始確認後に設定保存を確定する。保存前に終了状態を再確認する。

入力機器が選択されている場合、AudioInputServiceの最初の試行について、機器のオープンとLtcDecoderの生成が完了した時点を通知する。LTCフレームの受信は成功条件ではない。Monitorは開始確認に最大10秒待ち、取消・失敗なら新しい入力を終了する。起動時の通常監視はバックグラウンドで同じ入力IDへの再接続を続ける。

形式を変更したら開始TCを新形式で再検証する。文字列の変換や自動修正はしない。

## 失敗・取消・競合

MonitorのConfigureとDisposeは直列化し、入力ワーカーを一組だけ持つ。入力状態・レベル通知は入力世代と取消状態を確認する。古い入力はその入力専用の時計しか更新できず、新しい入力の時計や状態を上書きしない。

新入力の開始や保存に失敗したら旧入力と旧時計の復旧を試み、保存済み設定は変えない。復旧にも失敗すれば両方の失敗を通知し、時計をERRORにする。復旧時に以前の同期映像や手動再生を自動的に再開することはない。入力切替や位置変更には準備待ち・一時的な無音があり、無瞬断を保証しない。
