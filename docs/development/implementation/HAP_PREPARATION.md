# 素材解析とHAP索引の管理

## この資料について

この資料では、共通解析サービスが素材情報とHAP索引をどこで作成し、どの範囲で再利用するかを説明します。準備時間、再読込、取消、素材差替え時の結果の扱いを確認するときに参照してください。

対応素材と再生の概要は、[現行仕様](../FINAL_SPEC.md#9-性能上限検証配布)を参照してください。この資料では、解析・索引の対応条件、保管量、寿命、取消と無効化を扱います。

## 全体の関係

共通解析は映像・音声・コンテナーの情報を、HAP索引はフレームの位置・サイズ・時刻を保持する。実際に再生するファイルハンドルや映像・音声バッファは再生側が所有する。

PreviewPlayerが所有するMediaAnalysisService内のHapIndexCacheを手動再生・Coordinator経由のLTC先読み・素材確認へ渡す。独立した永続キャッシュや静的な全アプリ共通キャッシュは作らない。動画・音声・コンテナーの情報は共通サービスが保持し、索引キャッシュから動画情報を逆取得しない。HAP索引は位置表のみの責務とし、MediaInfoに付いた素材版と索引取得時の版を照合する。共通サービスの明示無効化は両キャッシュへ伝え、進行中の古い結果も採用しない。

共有対象は小さい解析結果のみ。HAP索引の保管量は4件/32MiB、音声復号は最大1プロセス、PCMは最大8ブロック。範囲外MOVのパケット索引用ffprobeと音声復号用FFmpegは、素材情報解析とは別の処理である。独立した回帰検証や旧部品のInspectAsyncは所有者を渡さない場合、既定では一時サービス、reuseAnalysis:trueのデコーダーでは自身の有界サービスを使い、製品ウィンドウのキャッシュとは共有しない。

## 通常の準備

### 素材情報の取得

共通サービスは登録・追加・リスト読込・手動プレビュー・LTC・共有音声・素材復旧に渡す。初回のffprobeは映像・音声の先頭ストリームとコンテナー情報を一度に取得し、各アダプターが用途ごとの時刻解釈・対応判定・通知文を適用する。映像開始の未指定はMediaInfoでは0、共有音声ではコンテナー開始へフォールバックする契約を維持する。

### HAP索引の作成

対応範囲のMOVでは、MovHapIndexがmoov内のサンプル表を読み、フレームのファイル位置・サイズ・時刻を構築する。mdatの映像本体は索引作成のために走査しない。後置moovもトップレベルのatomサイズで直接移動し、32bit/64bitチャンク位置を扱う。索引は位置情報を保持し、実フレームの読取・HAP展開・GPU提示は再生側で行う。

構造は[Appleのsample atomの説明](https://developer.apple.com/documentation/quicktime-file-format/using_sample_atoms)、[sample-to-chunk](https://developer.apple.com/documentation/quicktime-file-format/sample-to-chunk_atom/sample-to-chunk_table)、[chunk offset](https://developer.apple.com/documentation/quicktime-file-format/chunk_offset_atom)に基づく。

高速経路は自己完結した非分割MOV、単一のHap1/HapYサンプル記述、stsz、stsc、stco/co64、sttsを対象にする。可変サイズ・可変時間も扱う。合成時刻のシフトはゼロに限り、編集リストは先頭0・速度1・メディア全長と整合する単一のものに限る。

### 準備状況の表示

画面の活動領域に、素材情報確認、HAPの準備待ち、再生位置情報の準備、フレーム読取・展開と対象ファイル名を表示する。根拠のない百分率は表示しない。短い処理では表示を遅らせ、表示のちらつきを抑える。

## 共有結果の寿命

既定で完成済み索引は最大4件、推定32MiB。実素材の索引は数万フレームであり、1フレーム64バイトにパス等を加えた保守的な概算で計上する。使用頻度の古い完成済み結果から除外する。上限を超える単一索引はその要求には返すが保管しない。実行中のストリームは必要な読み取り専用参照を保持できるため、キャッシュから除外されても再生は止まらない。この参照と一時的な解析メモリーは、保管量の32MiBとは別であり、復号数・入力サイズの上限でも制限する。

完成結果はLRUで最大8件、JSONは1件1Mi文字まで（UTF-16で最大約2MiB、既定の保持文字列は合計約16MiB）。未完了のワーカーは取消処理中も含め最大8件、実際の解析は1件ずつ。解析と同期的Process.Startはワーカー上で行う。OSの同期的Process.Start自体は取消で中断できないため、その途中の取消は起動復帰後に直ちに子プロセスへ適用し、終了処理もその復帰を待つ。版は正規化パス・長さ・更新/作成時刻で、解析前後・返却前に照合する。利用者の取消は待機だけを終了し、全利用者の取消で解析を止める。失敗・取消・途中JSONを保持せず、終了時は解析を取り消して完了を待ち、メタデータと索引を解放する。

## 失敗・取消・素材変更

非ゼロの時刻シフト、複雑な編集リスト、外部データ参照、分割MOV、圧縮moov、stz2等の範囲外の構造は、ffprobeによるパケット索引経路を使う。未対応構造と破損を区別し、サイズ不正・範囲外参照・テーブル件数不整合は素材エラーにする。破損を高速経路と互換経路で繰り返し試さない。互換経路は素材によってパケット解析の読込時間がかかる。

同時の索引構築は1件、未完成の共有要求は最大8件。キーは正規化パス、ファイル長、更新時刻、作成時刻で、作成前後にも照合する。同じ素材版の複数利用者は一つの解析を待つ。一人の取消は他の利用者を取り消さず、全員が待機を終了すれば未完成の解析を取り消す。失敗・取消による途中結果は保管しない。

実行中のファイルハンドル、復号フレーム、PCMは保管しない。素材エラー通知では該当パスの再利用を無効にする。結果採用時にはキューID・素材世代・要求世代を確認する。全ファイルを毎回ハッシュしないため、長さ・全時刻属性を意図的に維持したままの変更を完全検出する保証はしない。

ファイル変更は版で検出し、素材監視の再検査・素材エラー・明示Refresh(forceRefresh:true)・リストの明示読込で無効化する。同じリスト内の重複パスは一度だけ強制更新する。行の保存済み情報だけでは再生を許可せず、同じ手動行でも素材版が変われば再読込する。行選択から解析や復号を始めない。素材版を意図的に維持した書換えの完全検出は保証しない。

進捗通知はUIへ渡す際にも要求・準備操作の同一性、取消、LTC権限を確認する。完了済み・取消済みの通知でIsBusyを復活させない。行選択と出力切替の動作は[現行仕様](../FINAL_SPEC.md#4-ltcと手動再生)を参照。

動画情報・音声情報の確認期限切れ、索引期限切れは説明付きのI/Oエラーにし、通常の利用者取消として黙って扱わない。解析の共有は、音声・映像の再生バッファやLTCの採用権限とは別に管理する。

## 索引の上限と構造検査

メタデータ64MiB、サンプル数100万、パケット128MiB、atom数10万等の上限を設ける。パケットが実際のmdat範囲内にあること、時刻表・サンプル数・チャンク表の整合を確認する。索引作成全体は60秒の期限を持ち、利用者の取消と期限切れを区別する。

## MOV読み取りの責務

MovAtomReaderが数値フィールド、atom境界、moov/mdat走査、基本テーブル件数、自己完結データ参照の検査を共有する。ファイル所有権・共有モード・例外方針・上限は呼出元に残す。HAPの時刻・サンプル索引とPCMのチャンク索引は独立し、PCMの時間フレーム数にHAPの100万サンプル上限を適用しない。
