# 操作と再生所有権

## 今回の範囲

行選択と素材準備を分離し、手動シークと保存の可否を外部出力から分離した。今回の次段階で、手動時の構成編集と同期中の表示順変更も解放した。設定変更のうち蓋絵の登録・差替え・解除も出力・同期中に解放した。LTC設定も種類別に解放した。複数選択・一括削除も実装した。

## 状態の責務

- `MainWindow.outputSessionActive`：外部映像出力の開始から停止までの寿命。映像出力先・方式・キャンバス変更の制限に使う。
- `PlaybackCoordinator.ManualAvailable` / `LtcHasPriority`：共通LTC時計からその場で導く再生の優先権。
- `PlaybackCoordinator.OwnsSurface` / `PreviewPlayer.IsSyncOwned`：同期セッションが表示面を所有しているか。LOSTでも保持画像は手動素材として扱わない。
- `MainWindow.previewCue` / `PreviewPlayer.LoadedPath`：実際に準備・表示した手動素材。DataGridの選択とは別。

UIの可否は `MainWindow.OperationAccess.cs` に集め、ボタン・シーク操作の入口とツールチップで同じ判定を使う。判定結果を別の権限フラグとして保持しない。

| 操作 | 条件 |
|---|---|
| 行選択 | 素材準備や表示変更をしない |
| 行の▶ | LTCが手動操作を許す状態で、素材準備・終了・出力切替中でない。キューの有効チェックやTCエラーは使わない |
| 停止・シーク | 上記に加え、表示中の手動素材があり、同期が表示面を保持していない |
| 保存 | 1件以上あり、LTC受信・再同期・補間中でなく、終了・編集適用・他の保存中でない。外部出力・手動再生・LOST保持・入力エラーは条件にしない |
| 構成編集・読込 | LTCが未受信（WAITING/LOST）なら許可。同期の保持画像や出力接続は条件にしない |
| 表示順変更 | 同期中も許可。出力切替・編集反映・終了中は不可 |

## 非同期処理の競合

UI判定の後でもLTC状態は変わるため、PreviewPlayerもCoordinatorのライブ権限判定を参照する。Load/Play/Seekは待機や準備の後、提示・再開の直前に権限・要求世代・取消を確認する。手動再生ループもLTC優先への移行を検出する。同期開始は従来どおり準備を取り消し、同じコマンド直列化を通る。同期と手動の別キャンバスや重複した時計は作らない。

## 保存

MainWindowは保存の寿命・ファイル選択・二重実行・終了時の取消を持つ。SaveContentAccessが内容と現在LTCによる可否を計算し、SaveAccessは保存操作中の二重実行拒否を加える。内容の条件はファイル選択後にも確認し、所有中の保存を自分自身で拒否しない。書込処理開始後のLTC取得では保存を取り消さない。ShowEditorはUIスレッドで一覧を独立したShowProgramDocumentにコピーする。ShowProgramServiceはそのDTOをJSON化し、保存先と同一フォルダーの一意な一時ファイルへ非同期で書き、完了後に置換する。取消・失敗時は一時ファイルを削除する。置換完了後の取消は完了済み保存を巻き戻さない。

保存はEditorの検証・素材解析・PlaybackChangedを起こさず、再生セッション、表示面、WASAPI出力、先読みを作り直さない。書込中の編集は保存用DTOに影響しない。終了処理は保存の取消と後始末を待ってから再生系を破棄する。

## 性能と将来の変更

行選択に伴うHAPの重い準備はなくなる。明示的な▶で必要な初回準備がなくなるわけではない。音声の並行準備、最初のフレームから継続利用する映像バッファ、有界キュー、単一WASAPI出力は維持する。

複数選択はDataGridのExtended選択に任せ、操作時に存在するCueIdの集合を取得する。再生コマンドは押した行を明示し、選択を書き換えない。一括削除は表示元を含む場合だけ既存の素材解放を一度行い、権限を再確認してからShowEditor.DeleteManyで全件変更後に一度だけ検証する。複製は単独選択時に限定し、ハンドル操作では1行だけを移動して選択ID集合を復元する。選択モデルの二重管理や選択による素材準備は追加しない。


## 構成編集とTC入力

TCのOneWayバインディングと一つの編集セッションにより、入力途中の値はCueRowに書かない。4欄の間の移動は同じセッションを維持し、Enter／外へのフォーカス移動でまとめて確定、Esc／LTC取得で取消す。確定直前にもライブ権限を再確認する。ShowEditor.SetTimecodeはプロパティ通知に伴う個別検証を抑制し、最後に一度だけ同期定義を公開する。

TC欄と有効チェックはDataGrid.IsReadOnlyから有効・フォーカス状態を導く。disabledスタイルでTC欄を灰色にし、無効時にもツールチップを表示する。行選択とドラッグハンドルは無効化しない。

構成操作はShowEditorのライブ権限コールバックでも拒否する。表示順変更には別の権限を使う。Importはリスト外で素材準備し、最後に権限を確認して反映する。Loadも準備完了後に権限を再確認する。編集の準備状態は設定処理のbusyと分け、LTCの受信・同期開始を妨げない。設定適用は編集準備との競合を拒否する。

表示元削除とリスト置換はPreviewPlayer.ClearAsyncで素材を解除する。停止して先頭フレームへ戻すStopAsyncとは別の責務。Clearも取消・コマンド直列化・同期優先の再確認を行い、表示元削除時に外部接続や蓋絵を解除しない。


## 未受信中の構成編集

LOSTで補間が終了したら、同期映像を保持していても構成編集を許可する。編集権限と手動映像の操作権限を区別し、保持映像へのシークは禁止したままにする。LTC復帰時には未確定TCを取消す。

ProgramPlaybackはLOST/ERRORの保持中、編集後のスケジュールを表示元として再選択せず、実際に開いていたactive素材を観測に使う。表示名・素材ID・保持位置・画素を維持する。予定は引き続き更新され、LTC復帰後に再評価する。PlaybackTimelineは開始位置・長さが変わった実行区間を引き継がない。

保持元の削除とリスト置換にはCoordinator.ClearHeldSourceAsyncを使う。同期開始と同じコマンド直列化の中で、未受信・期待する保持元を確認し、古い同期実行を終了して素材を解除する。待機後のLTC状態も確認し、受信が復帰したらクリアと削除を中止する。別キューの削除では同期の保持状態を解除しない。外部出力・蓋絵は維持する。


## 蓋絵の差替え

MainWindow.CoverChangesは画像選択・取消・終了待ちを独立して管理する。蓋絵の変更はLTCによる再生位置の所有権と無関係に許可する。別の設定反映・画像準備・終了・共通GPU障害中は拒否する。設定適用側も画像準備との競合を拒否する。

CPUでの画像読込後、RenderSession.PreparedCoverでGPUテクスチャを作成する。この段階では現在画像を変更しない。PendingSettingsの保存を成功させた後、awaitを挟まず、確保済みGPU資源・CPU画像・設定を確定する。GPUの確定操作は新たな割当を行わない。失敗・取消で未確定資源を破棄しても、元の画像は残る。

PreviewHostのCoverBindingへ確定済み画像を伝え、次のフレームで同じ画像を再アップロードしない。表示量・遷移開始時刻・目標は変更せず、保持画像でも再合成して反映する。保存する設定は画像準備完了時点のものを基にし、準備中の音量・フェード変更を戻さない。

設定適用経路でも同じGPU準備・確定を利用する。キャンバスを変更する場合は新しいキャンバス上で画像を準備する。共通GPU障害は画像単独の準備失敗と区別し、従来の停止経路に従う。画像のGPU転送・設定保存には実行負荷があり、物理的な完全無瞬断を保証するものではない。

## LTC設定

補間・再同期閾値はMasterClock.UpdatePolicyで設定値だけを変更し、次のAcceptから使用する。現在の受信に使用中の補間時間は別に保持し、設定変更だけでLOSTやERRORを解除しない。補正はCoordinatorが持つ設定値とSyncRunの固定値を区別し、値が異なる受信中の旧実行から映像・音声を採用しない。LOST保持は維持し、次の実受信で実行を更新する。

入力接続の変更ではCoordinatorのコマンド直列化を通して同期所有権を解放し、その同期素材を黒・無音へ戻す。手動素材は停止しない。Monitorは入力処理を一組だけ持ち、新旧の状態通知を世代で区別する。新入力の機器オープンとデコーダー生成の完了を待ち、保存に成功した後で設定を確定する。失敗時は旧設定の入力と時計を復旧する。復旧も失敗するとERRORと明示的な失敗を返す。実機の切替は無瞬断ではない。詳細はLTC_SETTINGS.md。

## 開始TCの一括編集

CueTimecodesはCSV・テキストの解析と、LTCフレーム単位での配置計算を担当し、ライブの行を変更しない。CueTimecodePlanは対象ID・元のTC・素材版・必要な長さと、新しいTCの読み取り専用リストを持つ。ShowEditor.SetTimecodesは現在の編集権限、形式、対象の存在・変更を確認してから全行を変更し、一度だけ検証する。単独TC入力も同じ反映処理を使い、不正TCをステータスとして残す従来の動作を保つ。

MainWindow.Timecodesは対象選択とモーダル画面の寿命を持つ。一覧順の変更も反映直前に確認する。CSV読み込みはサイズ制限と終了時の取消を持ち、LTC受信は妨げない。追加方式の保存は既存のPendingSettingsで確定してからライブ設定へ反映し、映像・音声・入力の再設定は行わない。

ShowEditor.ImportAsyncは既存と同じく一覧外で素材を準備する。自動配置時は追加直前の一覧から最も遅い終了時刻を求め、追加する全行の開始TCを計算してから反映する。計算失敗やLTC取得で一部だけ追加しない。複製と通常の0時追加は従来の動作を保つ。
