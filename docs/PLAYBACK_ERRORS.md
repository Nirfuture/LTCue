# 素材エラーと再生状態の管理

## 責務

- `ShowProgramService.Evaluate`：I/OなしでTC・重複・素材状態を評価し、予定と行の問題を返す。素材のエラーを消さない。
- `CueRow`：利用者の有効指定、検証結果、素材結果を保持。`ShowEditor`がUIスレッドで更新する。
- `MaterialMonitor`：登録済みパスの通知と定期確認、バックグラウンドの解析・フレーム確認。UIや再生を直接操作しない。
- `PlaybackTimeline`：映像と音声が共有する唯一の同期選択。ロック内ではI/O・待機・UI呼び出しをしない。
- `ProgramPlayback`：現在・次・追従復旧用のバッファと映像提示。素材失敗をTimelineへ通知し、GPU障害は全体障害へ渡す。
- `AudioOutputService`：共通Timelineから得たプレイヘッドを時計で進め、専用ワーカーで音声出力する。素材失敗と機器失敗を区別する。
- `MainWindow`：接続操作と状態表示。外部出力接続にキューの再生可否を使わない。

再設計は新しい汎用イベント基盤を追加せず、既存Coordinatorと小さな同期状態クラスを使う形とした。音声の準備許可・実出力許可、PCM上限、通常開始位置、WASAPI、PTS正規化は維持する。

## 状態遷移

Timelineは実行をIdle／Active／Failedで管理する。次の素材の準備失敗はその素材の除外だけに反映。実行中の失敗ではFailedへ遷移し、黒・無音で待機する。次の正常キューまたは復旧済み素材を選択できるまで前のキューへ戻らない。LTC世代変更では時刻に従って選び直すが、失敗した素材自体は確認成功まで再採用しない。

素材復旧は新しいSourceRevisionとして予定へ反映する。同じキューIDでも新しい素材なら再準備する。無関係な予定更新では現在の同期セッションを作り直さない。音声はSourceRevisionも識別して古いPCMを引き継がない。

## 古い結果の遮断

素材のSourceRevisionはプロセス内で一意に発行する。素材確認結果にはキューID、パス、SourceRevision、MaterialStatusRevisionを含め、現行行と一致した場合だけ適用する。確認中に新しい失敗が発生した場合も、古い成功結果で解除しない。リスト再読込後の同じIDに古い結果が届いても素材世代が異なるため採用しない。

## 自動検出・復旧の限界

ファイルシステム通知をきっかけに確認し、約1秒の待機と200msの通知集約を組み合わせる。通知漏れ・監視できないフォルダーも定期確認で補う。瞬時の検出は保証しない。

存在するだけでは復旧しない。サイズ・更新時刻が次の確認でも同じで、情報取得・フレーム読込が成功した後に復旧する。素材確認は同時1件、再生／音声準備中は新しい重い確認を控える。このため復旧に時間がかかる場合がある。

不変の破損ファイルは無制限に開き直さない。ファイル版の変更、不在からの復帰、手動の再生成功を復旧契機にする。変更通知もファイル版変化もない一時的I/O障害は自動復旧を保証しない。

HAP等は開いている間の通常削除がOSに拒否される場合がある。パスが不在でも現在の開いたストリームが正常ならその実行は続け、次回開始は不可とする。実ストリームの失敗で黒に移る。冒頭の確認成功は全フレームの完全性保証ではなく、後続の実行失敗も同じ経路で処理する。

終了待ちは既存の有界バッファ・キャンセル処理を維持する。任意のネットワークドライブのOSファイル問い合わせが即時取消しできる保証はない。素材監視をUIや音声ワーカー上では行わない。

## 読み込み・保存

空／重複IDは一時リストの段階で修復し、通常のTC変更・並べ替えではIDを変更しない。修復したJSONは自動上書きせず次の通常保存で反映。素材エラーやTC重複を含むリストも保存可能。壊れたJSON・未対応形式・件数上限は読込を拒否し、元のリストを維持する。


保存は表示用の検証や素材確認を実行せず、一覧のDTOを作る。再生中にも保存でき、保存取消・書込失敗では既存ファイルを保持する。行選択自体は素材再確認の契機にせず、明示的な行の▶または素材監視によって確認する。操作権限の詳細は[操作と再生所有権](OPERATION_ACCESS.md)を参照。
