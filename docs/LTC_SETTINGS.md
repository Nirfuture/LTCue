# LTC設定の個別適用

外部映像出力の接続と、LTCによる再生位置の所有権を分ける。設定の違いに応じて必要な資源だけを更新する。

| 設定 | 反映 | 維持するもの |
|---|---|---|
| 補間時間・再同期閾値 | 次に実際に受けたLTCフレームから使用 | 時計、入力、同期実行、動画、音声、GPU、出力接続 |
| 補正フレーム数 | 手動には影響なし。受信中は新しい目標へ再同期。LOST保持は次の実受信まで維持 | 入力、時計、音声出力機器、GPU、蓋絵、索引キャッシュ |
| LTC入力機器・チャンネル・形式 | 同期素材を黒・無音にし、旧入力終了→新入力開始確認→保存→確定 | 外部出力、GPU、蓋絵、音声出力機器。手動素材は維持 |
| 映像出力先・方式・キャンバス | 外部出力停止後に変更 | 従来の制約を維持 |
| 音声出力機器 | 音声OFF後に変更 | 従来の制約を維持 |

## 時計と補正

MasterClockは設定値と現在受信に使う補間時間を区別する。UpdatePolicyは設定値だけをロック内で更新する。Readは現在受信に採用済みの補間時間を使い、設定変更だけでは基準位置、世代、日跨ぎ、ERRORを変更しない。Acceptは以前の補間時間で受信途絶を判定し、新しい閾値でジャンプを判定した後、新しい補間時間を採用する。これにより、補間時間の延長でLOSTが復活しない。

Coordinatorは設定済みの補正とSyncRunに固定された補正を持つ。受信中に不一致があれば、旧実行の映像提示・観測・音声位置を採用しない。次のReconcileで旧実行を終了し、新しい補正の目標へ再同期する。LOST中は旧実行を保持し、新しい実受信が来た時に更新する。新しい時計や別プレイヤーは追加しない。

## 入力切替と失敗

AudioInputServiceの最初の試行について、機器のオープンとLtcDecoderの生成が完了した時点を通知する。LTCフレームの受信は成功条件ではない。Monitorは開始確認に最大10秒待ち、取消・失敗なら新しい入力を終了する。起動時の通常監視は従来どおり背景で同じ入力IDへの再接続を続ける。

MonitorのConfigureとDisposeは直列化し、入力ワーカーを一組だけ持つ。入力状態・レベル通知は入力世代と取消状態を確認する。古い入力はその入力専用の時計しか更新できず、新しい入力の時計や状態を上書きしない。

MainWindowは画像・GPU資源・保存用一時ファイルを先に準備する。入力を切り替える場合はCoordinatorの所有権直列化を通して同期を解放し、黒・無音にする。手動素材は保持する。新入力の開始確認後に設定保存を確定する。保存前に終了状態を再確認する。

新入力の開始や保存に失敗したら旧入力と旧時計の復旧を試み、保存済み設定は変えない。復旧にも失敗すれば両方の失敗を通知し、時計をERRORにする。以前の同期映像や手動再生を勝手に再開する補償処理は追加しない。入力切替や位置変更には準備待ち・一時的な無音があり、無瞬断を保証しない。

形式を変更したら開始TCを新形式で再検証する。文字列の変換や自動修正はしない。

## 検証

`--verify-ltc-settings`で時計の境界状態、手動・同期・LOST、資源の維持、補正後の音声位置、入力開始待ち・切替失敗・保存失敗・復旧失敗・古い通知・終了取消を検証する。入力切替の成功・失敗は検証用入力で再現するため、実際の機器・ケーブルを切り替えた物理検証とは区別する。
