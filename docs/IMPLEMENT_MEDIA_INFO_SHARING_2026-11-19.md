## 3. 背景と対象範囲

対象素材はデフォルト登録のHAP_1～4_1080p_2997_10s.mov。通常版同梱素材とのハッシュ一致を確認済みです。環境Aで各素材×音声OFF/ON×初回/停止後2回を計測しました。

- 初回の連続映像提示：約1.21～1.25秒
- 停止後の同一素材の連続映像提示：約37～48ms
- 音声開始：初回約2.37～2.40秒、停止後約0.60～0.62秒

これらは内部play_requestからのAPI復帰時刻です。クリック入力や物理AV遅延ではありません。video_playback_first_presentは先頭フレーム提示後の次の変更フレームを記録するため、video_first_present、video_clock_startも併記してください。

登録ではShowProgramService.RefreshAsync、読込ではMediaDecoder.InspectAsyncとPreviewAudio.InspectAsync、共有音声ではAudioMediaInfo.InspectAsyncが別々に情報取得します。この重複が対象です。

既に映像バッファの継続使用、手動音声の並行準備、HAP索引の共有は実装されています。今回それらを作り直さないでください。音声用FFmpeg起動の約0.55秒は別問題で、情報共有だけでは消えません。

## 4. 実装の方針

### 4.1 共通の解析結果とサービス

ウィンドウまたは再生セッションが所有する共通の解析サービスを導入してください。ファイルの初回解析では1回のffprobeで映像・音声に必要な情報を取得し、登録・プレビュー・共有音声で再利用します。

既存のMediaInfo、PreviewAudioInfo、AudioMediaInfoに必要な全情報を維持してください。特に映像開始、音声開始、コンテナー開始の時刻情報を省略しないでください。現在のcodec/tag、SAR、寸法、duration/fps、音声対応判定と不正素材の拒否を維持します。各呼出し元の表示・エラー契約も確認してください。

既存APIへのアダプター等を使い、時計・再生・同期層への影響を小さくしてください。src/LtcPlayer.Appの共有コードはAvalonia以外のプロジェクトや計算系試験にも利用されているため、Avalonia固有型への依存を持ち込まないでください。

### 4.2 キャッシュの正しさと寿命

- 正規化パス、ファイル長、更新/作成時刻などで素材版を識別し、解析前後で照合する。
- 同一版への並行要求は1回の解析にまとめる。
- 利用者1件の取消で、他の利用者の解析を止めない。全利用者の取消と終了処理を扱う。
- 失敗・取消・途中結果は保持しない。素材変更・素材エラー・明示再読込/復旧時の無効化を設計する。
- 保持上限と所有者を明示し、少なくともデフォルト4本を保持できる構成にする。無制限や静的な全アプリ共通キャッシュにしない。
- HAP索引キャッシュとの責任分担を明示し、片方だけ古い版を使う状態を防ぐ。
- ハンドル、PCM、復号フレーム、実行中の再生状態は保管しない。
- 重い解析と同期的なProcess.StartでUIスレッドを塞がない。これは操作応答と開始時間を別々に評価する。

現行の音声解析キャッシュ最大2件という仕様は、解析結果の共通化で責務が変わるため、残すか置き換えるかを明示し、必要な仕様文書だけを更新してください。音声復号1プロセス・PCM8ブロック等の実行資源上限は変更しません。

### 4.3 段階的に接続する

1. 共通解析と版管理・キャンセルを実装する。
2. 素材登録とプレビューに接続して重複削減を確認する。
3. 共有音声へ接続し、既存の時刻解釈・対応判定を維持する。
4. 素材復旧、リスト読込、LTC側など他の解析入口を確認し、対象外を含め利用範囲と残るffprobe呼出しを説明する。

単なる音声解析の削除や、CueRowの保存値を無条件に信用する方法では完了としないでください。共通化によって不要になった旧キャッシュや解析コードは利用箇所を確認して整理してください。

## 5. 維持する仕様・対象外

- 行選択では素材解析・HAP索引・静止画・音声準備を開始しない。明示的な▶を入口とする。
- 音声事前復号、選択/停止後/次キューの先行準備、FFmpegプロセス保持、PCMキャッシュ、プロセス内音声復号は実装しない。
- 音声を待つために映像時計の開始を遅らせない。共通時計、LTC優先権、世代による旧結果の拒否、同期補正を維持する。
- GPU描画、HAP展開、音声出力方式、設定/保存プログラム形式、操作UIは変更しない。
- BIOS、電源、セキュリティ設定を変更しない。利用中の通常アプリを終了しない。

## 6. 計測と検証

検証入口StartupMeasurementVerificationには未コミットの--startup-audio on|off対応があります。既存計測証跡は上書きせず、新規フォルダーを使ってください。専用の検証ビルド・独立設定・ゲイン0を使い、conditions.jsonと素材/バイナリ/ソース版の記録を照合してください。

必要な計測を追加し、解析の開始/終了、キャッシュヒット、実際のffprobe起動回数、再生要求、先頭提示、時計開始、音声開始を区別してください。通常ビルドでは検証用計測を除外します。

変更前後で同じ素材・条件を使って比較します。

- デフォルト4本、音声OFF/ON、初回と停止後の再生。
- 同一アプリ内の1→2→3→4→1切替。
- 各条件で初回1回＋停止後再生を少なくとも4回とし、初回と反復を混ぜず保存。全体初回のばらつきが結論に影響する場合だけ独立起動を追加する。
- 登録/リスト読込時間も記録し、再生前に移した待ち時間を隠さない。
- 外部出力OFF/ONの動作維持を対象スイートで確認。性能比較の条件を混ぜない。

構造上の目標は、同じ版の登録済み4素材を保持している状態で、再生要求後の「素材情報取得用ffprobe」が0回になることです。対応外MOVのHAP索引用ffprobeは別集計し、音声復号FFmpegとも区別します。キャッシュ追い出し/変更後の再解析は正しい動作として記録します。速度目標は保証値にせず、中央値・最大・初回値と残存工程を報告してください。

重点的に確認する項目：

- 同じ版の共有、同時要求、1利用者/全利用者の取消、失敗後の再試行、上限と終了時解放。
- 素材差し替え、明示再解析、ファイル変更中の解析、古い結果の採用拒否。
- HAP/HAP Q、H.264/AAC、PCM、音声なし、非対応音声、不正素材、開始時刻ずれ（late/early PCM）。
- 行選択で準備しないこと、再生連打/即停止、シーク、音声ON/OFF、LTC所有権移行と復帰。

この変更の共有・無効化・取消に意味のある試験を追加し、既存の対象スイートを実行してください。最終候補では正式scripts/test.ps1の全スイート（開始時カタログは55、追加した場合はその実数）と通常版ビルドを完了してください。合格のための期待値緩和は行わず、別問題が出たら原因と証跡を分けて報告します。

.NETはC:/Program Files/dotnet/dotnet.exe、global.jsonのSDK 10.0.203を使用。FFmpeg/ffprobeはユーザー通常導入先を確認し、既存プロセスの古いPATHに注意してください。通常導入先は次です。

%LOCALAPPDATA%/Programs/FFmpeg/8.1.2-full/ffmpeg-8.1.2-full_build/bin/

scripts/build.ps1 -Verificationで専用出力先を指定し、最終の正式テストはdocs/VERIFICATION.mdに従ってください。成果物は既存artifacts/env-a-final-v2を上書きしないでください。
