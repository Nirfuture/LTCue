# HAPの準備と解析結果の再利用

## 初回の索引作成

対応範囲のMOVでは、MovHapIndexがmoov内のサンプル表を読み、フレームのファイル位置・サイズ・時刻を構築する。mdatの映像本体は索引作成のために走査しない。後置moovもトップレベルのatomサイズで直接移動し、32bit/64bitチャンク位置を扱う。実フレームの読取・HAP展開・GPU提示は従来の経路を使う。

構造は[Appleのsample atomの説明](https://developer.apple.com/documentation/quicktime-file-format/using_sample_atoms)、[sample-to-chunk](https://developer.apple.com/documentation/quicktime-file-format/sample-to-chunk_atom/sample-to-chunk_table)、[chunk offset](https://developer.apple.com/documentation/quicktime-file-format/chunk_offset_atom)に基づく。

高速経路は自己完結した非分割MOV、単一のHap1/HapYサンプル記述、stsz、stsc、stco/co64、sttsを対象にする。可変サイズ・可変時間も扱う。合成時刻のシフトはゼロに限り、編集リストは先頭0・速度1・メディア全長と整合する単一のものに限る。

非ゼロの時刻シフト、複雑な編集リスト、外部データ参照、分割MOV、圧縮moov、stz2等の範囲外の構造は、既存のffprobeによるパケット索引経路を使う。未対応構造と破損を区別し、サイズ不正・範囲外参照・テーブル件数不整合は素材エラーにする。破損を高速経路と互換経路で繰り返し試さない。互換経路は素材によって従来の読込時間が残る。

メタデータ64MiB、サンプル数100万、パケット128MiB、atom数10万等の上限を設ける。パケットが実際のmdat範囲内にあること、時刻表・サンプル数・チャンク表の整合を確認する。索引作成全体は60秒の期限を持ち、利用者の取消と期限切れを区別する。

## 共有するものと寿命

PreviewPlayerが所有するHapIndexCacheを手動再生・Coordinator経由のLTC先読み・素材確認へ渡す。独立した永続キャッシュや静的な全アプリ共通キャッシュは作らない。動画情報は完成した索引と併せて再利用できる。音声解析の既存キャッシュとは別の責務。

既定で完成済み索引は最大4件、推定32MiB。実素材の索引は数万フレームであり、1フレーム64バイトにパス等を加えた保守的な概算で計上する。使用頻度の古い完成済み結果から除外する。上限を超える単一索引はその要求には返すが保管しない。実行中のストリームは必要な読み取り専用参照を保持できるため、キャッシュから除外されても再生は止まらない。この参照と一時的な解析メモリーは、保管量の32MiBとは別であり、既存の復号数・入力サイズ上限でも制限する。

同時の索引構築は1件、未完成の共有要求は最大8件。キーは正規化パス、ファイル長、更新時刻、作成時刻で、作成前後にも照合する。同じ素材版の複数利用者は一つの解析を待つ。一人の取消は他の利用者を取り消さず、全員が待機を終了すれば未完成の解析を取り消す。失敗・取消による途中結果は保管しない。

実行中のファイルハンドル、復号フレーム、PCMは保管しない。素材エラー通知では該当パスの再利用を無効にする。既存のキューID・素材世代・要求世代による結果採用の確認は引き続き必要。全ファイルを毎回ハッシュしないため、長さ・全時刻属性を意図的に維持したままの変更を完全検出する保証はしない。

## 表示と取消

既存の活動領域に、素材情報確認、HAPの準備待ち、再生位置情報の準備、フレーム読取・展開と対象ファイル名を表示する。根拠のない百分率は表示しない。短い処理は従来の遅延表示を使う。

進捗通知はUIへ渡す際にも要求・準備操作の同一性、取消、LTC権限を確認する。完了済み・取消済みの通知でIsBusyを復活させない。行選択では準備しない。出力ON/OFFもキャッシュ・キャンバス・同期・音声を作り直す理由にしない。

動画情報・音声情報の確認期限切れ、索引期限切れは説明付きのI/Oエラーにし、通常の利用者取消として黙って扱わない。音声の並行準備、有界バッファ、単一WASAPI出力、映像バッファの継続使用、LTCの採用優先は維持する。
