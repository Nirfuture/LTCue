# 現行実装仕様（preview.11開発候補）

2026-11-13。fix/preview10-display-disconnectのpreview.11開発候補を対象とする。公開済みpreview.10の記録は[確認記録](releases/0.1.0-preview.10.md)を参照。現行仕様の基準は本書。旧要件・再設計案・進捗記録は経緯を示す資料とし、旧記述を読み替えて利用する必要がないよう、現在の動作をここにまとめる。旧仕様本文は[履歴](history/FINAL_SPEC-before-preview.10.md)に保存する。

## 1. 対象と構成

Windows 11 x64、Avalonia/.NET 10、WASAPI/libltc、FFmpeg、D3D11を使用する。MP4/H.264、MOV/HAP・HAP QをLTCに同期、または手動で再生する。単一の共通GPUキャンバスへ映像と蓋絵を合成し、縮小プレビューと単一の外部ディスプレイへ渡す。

外部映像出力は表示先の追加・解除だけを行い、再生時計・キュー位置・蓋絵のフェード・音声をリセットしない。プレビューと外部映像は同じ合成結果を使う。縮小補間や提示時刻の違いは許容し、物理画面の同時発光は保証しない。

ネットワーク配信、Genlock、複数独立タイムライン、動画間クロスフェード、ASIO、音声のマルチチャンネル出力は対象外。

## 2. 画面と初期状態

上部に青いLTC時刻、受信状態、出力開始・停止、設定。横長ではキュー一覧と右側のプレビュー・音声出力・蓋絵を2列に配置する。幅1100未満または高さが幅以上の画面は縦積みとし、高さ不足はスクロールで扱う。高さが低いことだけを理由に3列へ分割しない。

警告は上部の固定1行へ表示し、表示・解除で下のUIを移動しない。長文は省略とツールチップを使う。再生情報は常時表示し、ファイル名の重複や内部状態名の表示を避ける。

再生情報の近くに「映像：遅延なし」「音声：遅延なし」を並べ、共通時計との差を統一表示する。映像の許容幅は50msと1.5フレーム分の大きい方、音声は50ms。許容幅を超えるずれが同じ方向へ0.3秒続くと「120ms遅れ／先行」のように10ms単位で表示する。復帰も0.3秒確認し、一時的な変化は「確認中」。準備中・再同期中・停止中・一時停止・OFF・音声なし・入力／描画エラーは別状態とし、未取得・古い音声測定値・旧世代の観測値を正常扱いしない。これは表示判定であり、既存の補正・復旧処理を操作しない。

通常起動時はテスト動画1〜4を有効登録し、開始TCを00:00:05:00、00:00:20:00、00:00:35:00、00:00:50:00とする。音声出力と蓋絵表示は毎回OFF。外部映像は自動開始しない。初回のLTC形式は29.97 DF、保存済み設定がある場合はその形式を使う。`--program`指定時は保存プログラムを優先する。

## 3. キュー編集と選択

動画の追加・削除・複製・JSON保存/読込、開始TC入力、有効切替、表示順変更を持つ。上限1000件。追加直後のTCは0、複製は元のTCを引き継いで初期無効。開始TCの同一時刻競合を禁止し、区間の重複は許可する。検証結果を「エラー」列へまとめ、全文はツールチップで確認できる。

現在時刻以前に始まった最新開始のキューを採用し、終了後に以前の長いキューへ戻らない。キュー外の区間は黒。次の開始TCのキューを先読みする。

表示順は左端の行全高ハンドルで変更する。現在位置も含む挿入境界へ青い線を表示する。一覧外・Esc・フォーカス/ポインター捕捉喪失で取り消す。表示順の変更と同内容の再検証は再生を再起動しない。開始TC・有効状態など、再生定義が変わった場合は反映する。

「有効」は1クリックで切替可能。行全体の選択・再生中の緑表示を残し、セルだけの選択枠やヘッダーのホバー強調は表示しない。ファイル名の右クリックからエクスプローラーで保存場所を開く。外部映像出力中は編集禁止。

## 4. LTCと手動再生

LTC監視はアプリ寿命で1組。出力開始・停止で開き直さない。形式は24、25、29.97 NDF、29.97 DF、30。L/R選択、補正（フレーム）、補間時間、再同期閾値を設定する。補正はフレーム数を選択形式のfpsで秒へ換算し、再生制御と同期表示で同じ換算を使う。逆方向・モード不一致を拒否する。DFは時刻のフレーム区切りを`;`とする。

| 状態 | 動作 |
|---|---|
| WAITING | 手動再生を許可 |
| LOCKED / RESYNC | LTC優先、手動再生・シークを拒否 |
| FREEWHEEL | 共通時計で補間を継続、手動操作は拒否 |
| LOST | 映像を保持、音声を無音化。手動再生を許可 |
| ERROR | 映像を保持し、音声と新たな手動再生を停止 |

既定補間0.1秒、再同期閾値2フレーム。同じ入力IDの再接続を試み、別機器へ自動変更しない。復帰・ジャンプ時は世代で旧要求・旧フレーム・旧音声を排除する。

行の選択は先頭映像を準備するが、自動再生しない。動画読込が取り消された場合は後続の再生へ進まない。手動再生は連続再生バッファの先頭を時計開始前に提示し、そのバッファを継続使用する。初回選択時の解析・静止画準備は別工程として残る。外部映像出力中の選択は映像を変えない。行の▶で手動再生、Ⅱで一時停止、■で停止する。一時停止後の▶は現在位置から、停止・終端後の▶は先頭から再生する。停止・終端では最後に表示した映像を保持する。

シークは映像直下のバーで、クリック・ドラッグ・キーボードを使用する。LTC同期中と外部映像出力中は操作不可。出力中の未受信・LOSTでは有効キューの先頭再生と停止保持を許可し、受信復帰でLTCへ戻る。

入力レベルは設定のLTC入力タブで、適用中の入力を使って測定する。ピークは500ms保持、300ms以上更新がない値は消す。dBFS、上限付近、受信状態を別表示し、未適用の機器を測定しているように見せない。

## 5. 外部映像とプレビュー

出力開始・準備中・出力中・停止確認・停止処理・停止を管理する。準備・停止中の連打を拒否する。停止ボタン・Esc・外部出力ウィンドウの閉じる操作・アプリ終了の確認は共通化する。確認中と取消時は出力を継続する。

出力は接続した指定画面へのボーダーレス最前面ウィンドウ。標準（Flip）を既定とし、不安定な環境では互換（BitBlt）を選べる。設定画面には切替の注意を残す。開始失敗・外部出力単独の障害は表示先を解除し、可能な限り共通再生を維持する。出力先の切断・表示構成変更では外部出力を停止し、別画面へ移さない。接続確認後の明示的な出力開始を必要とする。

プレビューは出力キャンバス全体を表示する。映像のアスペクト比と黒帯は共通合成に含め、出力寸法・比率と青い外枠で範囲を示す。縮小は各辺を最大1/2、総画素数を最大1/4とし、表示領域の実ピクセル寸法も上限にする。更新目標30fps、保留は1枚以下。通常経路にCPU読戻し・GPU完了待機を入れない。元動画の復号負荷が1/4になるという意味ではない。

短い準備でプログレスバーを点滅させず、180ms経過後に固定領域へ表示する。進捗の有無で映像の位置やサイズを変えない。

## 6. 音声出力

音声は内容確認用で、本番音声出力の保証は対象外。手動再生・LTC同期のどちらでも、スピーカーボタンをONにすると共通再生位置に対応する音声を1系統で出す。AAC・PCM系、48kHzステレオ、WASAPI共有モード。音声なし・非対応は状態として通知し、映像を継続する。

起動時は必ずOFF。出力先と音量を保存するが、ON状態を復元しない。出力先は音声OFF時に設定パネルで選び、ON時に実デバイスIDへ固定する。「システム既定」もON時の接続先へ固定し、既定機器が変わっても勝手に転送しない。エラー時はOFF→ONで明示的に再試行する。

スピーカーボタンは出力開始・停止、音量0は無音での追従。外部映像の開始・停止・確認取消・蓋絵・フェードで音声を切り替えない。一時停止・停止・終端・LTC LOST/ERROR・キュー外では未再生バッファを破棄して無音化する。映像時計は音声を基準に巻き戻さず、音声が現在位置へ追従する。

手動再生では音声の解析・復号を映像ストリームの準備と並行して開始できるが、時計が進むまで音声を出力しない。準備量は有界キューに制限し、停止・読込取消・対象変更で古い要求を無効化する。

音声解析キャッシュは最大2ファイル、復号は1プロセス、PCMは8ブロック。音声準備・デバイス待ちを映像ループへ持ち込まない。WASAPI投入目標は30ms分で、微小ドリフトをレート補正し、大きいずれは再同期する。内部PTSと物理的な出音の遅延は別に測定する。

再生位置の有効性と通知の鮮度は区別する。手動再生の時計は開始から一時停止・停止・終端・失敗まで有効とし、描画通知が遅れただけでは音声を再準備しない。観測値だけを供給する経路は250msで失効する。LTC再生では音声と映像が同じ不変のキュースケジューラーを参照し、入力状態・世代で有効性を判断する。機器の切断・表示構成変更に伴う一時的な音切れは許容し、復帰後は現在の基準時刻へ追従する。無瞬断は保証しない。

## 7. 蓋絵

メイン画面でPNG/JPEGを登録・解除する。未登録・起動時の読込失敗は黒。アスペクト比を維持し、余白・透過は黒。切替時間は0〜60秒、初期値1秒、0秒は即時。上下矢印を出さず、直接入力とプリセットを使う。途中反転は現在の濃さから指定時間で遷移する。

画像パスと時間を保存し、表示ON状態は起動時リセット。登録・解除は外部映像出力停止中のみ。蓋絵中も裏で再生し、音声は独立して継続する。GPUで合成し、フェード量を累積させない。

## 8. 設定・保存・障害

設定はLTC入力・音声出力・映像出力の3タブ。「適用」は閉じずに反映し、「閉じる」は未適用分だけ破棄する。変更欄・タブを強調し、変更がない場合は適用不可。機器更新は円形矢印。外部映像出力中はLTC・映像設定を固定し、音声出力先は音声OFF時に変更できる。

未接続の映像出力先を保持し、無関係な設定適用で先頭画面へ変更しない。映像出力先がない場合も入力・音声設定を適用できる。新しいキャンバスと保存ファイルを準備し、保存成功後に確定する。失敗時は旧キャンバス・蓋絵・設定を保ち、必要なら旧入力を復旧する。入力復旧は無瞬断ではない。適用失敗後に手動再生を勝手に再開しない。

プレビュー単独障害は既存の情報欄へ通知し、外部映像と音声の操作を維持する。共通GPU障害では映像再生・外部出力を停止し、再生に追従する音声を無音化する。入力監視を残し、失敗したGPUセッションを自動再起動せずアプリ再起動を案内する。

上演JSONはVersion1、上限4MiB。相対素材パスはJSON位置を基準とし、読込時に再検査する。前回の上演を自動復元しない。設定は実行フォルダーのphase2-settings.jsonへ一時ファイル置換で保存する。

診断ログはLOCALAPPDATA/LtcPlayer/logs、1セッション8MiB、合計256MiB、最大10記録/秒。有界キューでI/Oを再生と分離する。上限・I/O失敗で再生を止めない。自動削除は行わない。

## 9. 性能上限・検証・配布

H.264はFFmpegでBGRA復号、HAP/HAP QはSnappy展開したBC1/BC3をGPUへ転送する。HAP alphaは非対応。HAPは寸法が4の倍数で正方形ピクセル。映像ストリームは現在・先読み/復旧を合わせ最大2。素材寸法上限8192×8192は実用性能の保証ではなく、主な検証は1080pで行う。

自動検証の入口は[一括検証](VERIFICATION.md)。実LTC、機器の抜差し、他の環境、2時間以上の耐久、物理的なAV同期は別工程で、未実施を合格扱いしない。

配布は.NETランタイム同梱のwin-x64。利用者による.NET Desktop Runtime/SDKの追加導入は不要。FFmpeg/ffprobeとVisual C++ x64ランタイムは外部前提。未署名プレビューとして扱い、実行用ZIPにはライセンス・AudioNativeの対応ソースを同梱する。正式リリースは指定コミットから、未コミットの候補は明示したソーススナップショットから作る。
