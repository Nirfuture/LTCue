## 現在の状態

- LTCを共通時計とし、映像・確認用音声が追従する。音声は本番用の保証対象ではない。
- メインに映像／音声の「遅延なし」「○ms遅れ／先行」「準備中／再同期中」などを表示。基準は共通時計。見出しはユーザー指定で「音声」、スライダー下の重複表示は削除。
- 外部画面切断時に全画面映像がメイン画面へ移る問題を対策。外部出力だけ停止し、再接続後は明示的に再開する。
- H.264の不要なCPU拡大を避けて既存GPU拡大経路を利用。手動再生の初期映像準備と、FFmpegの微小シーク時刻表記を修正。
- JSON読込時の全体検証は最後の1回に集約。音声時計の寿命を明示し、音声と映像で同じスケジューラーを共有。
- 縦長出力選択時のプレビュー枠更新漏れを修正。スクロール／縮小時のはみ出しは、内側の映像面だけでなくAvaloniaから渡された外側ホストに切り取りを適用する。ホストの所有・破棄はAvaloniaへ任せる。

## 未解決・次の優先事項

1. **音声開始が遅い。未修正。** 既存試験では約0.55～1.14秒、実機ログでは映像開始から約1.1秒後に音声開始。古い音を捨てて現在位置から合流するが、開始待ち自体が改善対象。ユーザーからは手動・LTCの両方で報告。直近の指示は「確認だけ」で、音声改善は実装していない。
2. 開始後も音が遅れ続けるかは未確定。既存ログの内部位置は概ね追従しているが、聴感上のずれを否定しない。AudioStartVerificationは開始後の同期を主に検査し、開始待ち時間の上限を合否にしていない。
3. 統一表示のLTC補正値に単位不整合の疑いがある。MainWindow.TimingStatus.csはsettings.Offsetを秒へ直接加えているが、再生側はOffset / Editor.Rate.Fps。非ゼロ補正で表示だけを誤判定する可能性があり、次回確認が必要。未修正。
4. プレビュー切り取りは修正前の誤った合格判定が複数回あった。最終候補では「縦長1080×1920・ウィンドウ高さ600」で外側の黒い領域まで収まることを目視確認。検証環境Bでも上下端・スクロール・高さ変更を再確認する。

## 検証環境Bでの開始

```powershell
git clone --branch main https://github.com/Nirfuture/LTCue.git
cd LTC_Player
./scripts/build.ps1
# PowerShell 7.2以降。FFmpeg/ffprobeをPATHへ入れて実行
./scripts/test.ps1
```

ビルドにはWindows 11 x64、.NET SDK 10.0.203、VS2022 C++ツールチェーンが必要。詳しくは[BUILD.md](BUILD.md)。通常ビルドの実行ファイルはartifacts/win-x64/LtcPlayer.Avalonia.exe。Gitには生成済みEXE、端末固有設定、実機ログを入れていない。まず新しいPCの入出力デバイスと画面を設定する。

方針：共通時計方式を維持し、表示判定と再生制御を分離する。無瞬断や別デバイスへの自動フォールバックを増やさず、単純な責務分担と明示的な復旧を優先する。許可なく見出しや用途を変更しない。
