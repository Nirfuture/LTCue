# 0.1.0-preview.4 配布前の確認記録

## 変更

- HAP解析とフレーム索引を出力セッション内で再利用。ファイルサイズ・更新日時の変更時は再解析。保持は最大2ファイル。
- 本番出力の全体像を保ち、出力先の縦横比に合わせてプレビュー枠を配置。
- 出力先と動画の解像度・縦横比を併記。
- 「配信」を「出力開始／出力停止」に変更。
- 表示フレーム数を通常画面から外し、スキップフレーム数と説明を表示。

動画だけを拡大する試作は採用していません。本番出力の描画内容と余白は変更していません。

## 確認

1080×1920（9:16）と3840×2160（16:9）の両出力先で、1920×1080（16:9）のHAP動画を出力し、出力枠の比率・領域内への配置・解像度表示・ボタンとカウンターの文言を確認しました。実画面でも縦向き出力の余白と動画の関係を確認しています。

出力操作9件、UI11件、追加機能5件、プレビュー・編集12件の回帰試験も通過しました。

HAP素材の反復シーク試験では、解析なしの初回フレーム取得が約1.1秒、解析再利用時は約2〜4ミリ秒でした。同じファイルの同時準備で解析・索引作成が重複しないことと、更新日時変更時の再解析も確認しました。

模擬LTCと実HAP・GPU出力で、入力喪失時の保持・受信復帰・前後ジャンプを確認しています。受信再開を3回繰り返した試験では、最初の映像更新まで約20〜51ミリ秒でした。物理音声入力や物理ディスプレイの遅延を含む測定ではありません。

## 既知の制約

- 解析結果が保持されていない動画の初回読み込みや、H.264の復号プロセス起動には引き続き準備時間が必要です。
- 未署名。Smart App Controlが有効な環境では起動をブロックされる場合があります。
- 物理ディスプレイ上の同期精度、他の環境、長時間運用は未確認です。
- 旧単体再生エンジンのPTS整合試験は、[前版までの確認記録](0.1.0-preview.2.md)のとおり保留です。
