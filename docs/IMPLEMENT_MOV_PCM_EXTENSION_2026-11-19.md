## 4. 実装前に確定する対応表と比較基準

### 4.1 PCM形式とMOV表現を分ける

目的の6組合せについて、実際に受け入れる以下の対応表を先に示してください。

- codec tagとサンプル記述version。
- 整数/IEEE float、符号、格納幅と有効ビット数、packed/配置、エンディアン。
- チャンネル数・配置、1 PCMフレームのバイト数、表のサンプル/パケット単位との関係。
- `stsd`拡張、`chan`、必要な場合のversion 1/2固有フィールドの扱い。
- 直接経路で受け入れるもの、未対応としてFFmpegへ戻すもの、破損として拒否するもの。

`sowt`、`in24`、`fl32`、`lpcm`など、名前とビット深度だけで同一視しないでください。`16`を`24`へ置き換えるだけの判定緩和や、格納幅を常に有効ビット数/8とみなす実装は避けてください。PCMの時間軸上のフレームと、MOV表のサンプル/パケット単位も混同しないでください。

全codec tag・全version・全格納表現の網羅は要求しません。ただし、目的の各組合せについて少なくとも一つの正常な実MOV表現を生成・検証し、直接読取を成立させてください。必要なサンプル記述への対応を、判定を緩めることで代用しないでください。未対応の表現は理由とともに明示してください。

内部に小さな入力形式記述を設けることは構いませんが、汎用デコーダー基盤にはしないでください。出力の48kHz・float32・stereoと既存ブロック契約は維持してください。

### 4.2 PCM値・音量・時刻の比較

同じFFmpegバイナリと現行の音声フィルター経路を基準にしてください。

- PCM値、サンプル数、PTS、先頭の実サンプル位置、シーク後の波形、末尾の扱いを別々に比較する。
- 許容誤差を形式ごとに定義し、変換・丸めの根拠を記録する。一律に誤差を大きくして合格にしない。
- モノラルのステレオ化は、既存FFmpeg経路のチャンネル変換と音量を基準にする。左右へ同じ値をコピーするだけで同等と決めつけない。
- 32bit floatのNaN・Inf・範囲外値は現行出力契約と整合させる。入力PCMの変換と出力段のクリップ等を区別し、特殊値が通常の誤差比較をすり抜けないようにする。
- 既存16bit stereoの結果を維持する。新形式が通ることだけで既存経路の回帰を合格にしない。

現在のゼロ開始、編集リスト、音声長と映像長の整合等の適用条件は原則として維持してください。追加形式のフレーム/パケット構造を正しく解釈するための変更と、開始時刻ずれ等の対応範囲拡張を混同しないでください。既存の時刻差素材は、引き続き正しいフォールバックを確認する対象です。

## 5. MOV低水準解析の共通化

重複を確認し、次の低水準部分に限定して共通化してください。

- atomヘッダー読取、32/64bitサイズ、サイズ0、境界・範囲・件数の検証。
- `moov` / `mdat`の探索と範囲の取得。
- 共通サンプルテーブルの基本的なフィールド/エントリー読取。
- データ参照の基本検証、外部参照・不正構造の検出。

次は映像・音声で独立したままとしてください。

- 索引の表現、時刻解釈、対応形式・対応構造の判定。
- ファイル所有者、開き方、リソース寿命、素材版の照合、取消と結果採用の境界。
- HAP索引キャッシュと、音声復号窓内のチャンク表の責務。

共通ヘルパーには、パーサーの都合でHAP側のストリームや音声の実行状態を所有させないでください。共通コードにAvalonia固有型への依存を導入しないでください。上限、例外、未対応と破損の区別、取消、ファイル共有ポリシーを一律に変えないでください。

**PCMの索引はチャンク単位の有界な構造を維持し、音声全フレーム分の時刻・パケット配列を生成しないでください。** HAP用のサンプル単位配列や100万サンプル上限をそのまま音声へ流用すると、48kHzでは約20.8秒で上限に達します。20.8秒を超える正常PCMも使って、この誤った共通化を防いでください。

無理な抽象化や汎用MOVパーサー化は避けてください。重複を残す方が安全で簡潔な箇所は、理由を記録して重複を維持して構いません。重複削減量そのものを目的にしないでください。

## 6. 維持する再生・資源契約

- 共通素材解析と素材版管理、同一版の再利用、変更・エラー・明示再解析時の無効化。
- LTCの時刻を基準とする音声同期、映像/音声の同期精度、世代による旧結果の拒否。
- 音声を待つために映像時計の開始を遅らせないこと。
- 停止・再開・シーク・素材切替・取消で、古いPCMを新しい要求へ引き渡さないこと。
- 音声ON/OFF、出力デバイス変更・エラーからの明示復旧。
- 音声復号窓1、音声FFmpeg最大1、PCMチャネル1024フレーム×8ブロック。
- UIスレッドを重い解析・同期的Process.Start・変換処理で塞がないこと。
- 停止・取消・失敗・終了時のファイル、メモリ、ハンドル、プロセスの解放。
- HAP映像の索引構築、キャッシュ、提示、素材差し替え、外部出力の既存動作。

PCMを全長保持したり、ブロックを大きくして実質的に上限を増やしたりしないでください。行選択を解析/準備の入口にしないでください。物理的なデバイス抜差しと失敗注入、実LTCと合成入力は区別し、未実施を合格扱いしないでください。

### 7.2 正常素材と異常素材

追加形式の正常系は、実際にその形式のPCMを格納したMOVを生成してください。生成コマンド、使用ツール版、ハッシュ、ffprobe等による形式確認に加え、必要なサンプル記述や格納表現も確認してください。テスト対象の共通ヘルパー自身による判定だけで素材の正しさを証明しないでください。

形式名、codec tag、チャンネル数などのヘッダーだけを書き換えた素材を正常系に使用しないでください。破損・偽装の負例として意図的に変更する場合は、その目的と変更箇所を記録してください。

少なくとも次を検証してください。

- 既存形式と追加5組合せそれぞれの先頭・中間・末尾・端数シーク。
- FFmpegとのPCM値・音量・サンプル数・PTS・シーク位置の比較。
- 24bitの符号境界、負の値、格納幅/エンディアン、floatの特殊値と範囲外値、モノラルの左右/音量。
- 複数チャンク境界、末尾の部分ブロック、20.8秒を超えるPCM、対応する32/64bitチャンク位置。
- 正常な対応外表現と44.1kHz等のフォールバック、破損atom・件数不整合・範囲外参照等の拒否。
- 素材版変更、解析/読取中の変更、準備取消、満杯キューでの停止、連打/即停止、再開・シーク・素材切替。
- LTC優先権・世代変更・喪失/復帰、音声ON/OFF、デバイス変更・失敗からの復旧。
- HAP/HAP Qの索引結果と実フレーム、先頭/中間/末尾、共有・追い出し・無効化・素材差し替え。
