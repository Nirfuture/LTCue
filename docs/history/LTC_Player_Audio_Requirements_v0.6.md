# LTC Player 音声出力要件 v0.6

2026-11-10 / 方針変更の仕様。実装・検証は未完了。

本書はv0.5の「確認用音声」、本番音声を対象外とする記述、外部映像開始時に音声を停止する記述を置き換える。他の映像・LTC・キュー・蓋画仕様は維持する。

## 1. 基本設計

共通再生の位置を基準として、映像と音声を生成する。画面内プレビュー、外部映像、音声出力はそれぞれ独立した表示・出力先とする。

- 外部映像の開始・停止は音声へ作用しない。
- 音声出力の開始・停止、ミュート、デバイス障害で映像の位置や時計を切り替えない。
- 手動再生とLTC同期のどちらでも、音声出力を有効にすれば対応素材の音声を出す。
- 音声は共通の再生位置へ追従する。音声の消費サンプル数を、映像時計の唯一の基準にしない。
- プレビュー用と本番用に音声を二重再生しない。音声出力先は初期実装では1つ、ステレオとする。

## 2. 音声出力の操作

- メイン画面に「音声出力」のオン・オフ、選択中の出力先、音量、ミュート、動作状態を表示する。
- アプリ起動時は音声出力オフ。以前オンだったことだけを理由に音を出さない。
- 出力先と音量は保存する。オン状態は保存・復元しない。
- 音声出力オフはWASAPIストリームと音声用FFmpegを終了する。再生位置・映像・LTC監視は継続する。
- ミュートは再生を継続して音量を0にする。解除時はその時点の位置を再生し、ミュート中の音声を後から流さない。
- 再生途中でオンにした場合も現在位置へ追従する。準備が遅れた古い音声を流さない。
- 外部映像の停止確認・取消・停止・開始失敗で音声を止めない。アプリ終了時は音声も終了する。

## 3. 出力先

- Windowsの音声出力デバイスを列挙し、選択できるようにする。LTCの入力デバイスと別に扱う。
- 「Windows既定」を選べるが、オンにした時点で解決した実デバイスIDへそのセッションを固定する。
- 選択先の切断・変更時に、別の機器へ黙って出力し直さない。音声を停止して理由を表示し、再開は利用者の明示操作とする。
- 出力先変更は音声側だけの操作。映像・LTC・GPU資源を再作成しない。
- WASAPI共有モード、48kHzステレオを初期方式とする。排他モード、ASIO、マルチチャンネル、複数同時音声出力は対象外。

## 4. 状態別の動作

音声オン状態と、実際に再生できる状態を分ける。例: Off / Preparing / Playing / Muted / Paused / Waiting / Resyncing / Error。

| 再生・入力状態 | 音声動作 |
|---|---|
| 手動再生 | 共通再生位置に対応する音声を再生 |
| 一時停止 | 音声を停止して位置保持。古いキューを残さず再開 |
| 手動停止・動画終端 | 音声は無音。映像の最終フレーム保持と区別する |
| LTC WAITING、手動再生なし | 無音 |
| LTC LOCKED | 対象キューのLTC経過位置へ追従 |
| LTC FREEWHEEL | 設定した補間期間だけ共通時計に従って継続 |
| LTC LOST | 音声を停止して未再生バッファを破棄。映像は保持 |
| LTC ERROR | 音声を停止して通知 |
| LTC復帰・前後ジャンプ | 古い世代を破棄し、新しい現在位置で再同期 |
| キューのない区間・音声なし素材 | 無音 |
| 蓋画表示・フェード中 | 元の音声を継続。音声を止める操作は独立 |

LOST中の手動再生を許可し、LTC復帰時は映像・音声とも同期を優先する。停止や世代変更時は、ソフトウェアとWASAPIへ投入済みの旧データを停止・リセットする。機器内部に残る音の終了時間は実測する。

## 5. 同期と復旧

- キュー選択、LTC変換、オフセット、世代の判定は共通再生から供給する。音声側に独自のキュースケジューラーを作らない。
- 音声ブロックはCueId、世代、先頭PTS、サンプル数を持つ。異なる世代やキューの旧データを再生しない。
- 音声と映像のPTSは同じ素材の再生原点に正規化する。音声ストリームの開始時刻差を無視しない。
- 共通時計とWASAPIの実消費位置・バッファ量を比較し、経路の遅延とドリフトを観測する。
- 微小なずれの補正と、大幅ジャンプの再シークを区別する。通常ドリフトでFFmpegを何度も起動し直す方式を避ける。
- 復旧処理は単一進行・有界とし、準備中に時計が進んだだけで破棄・再作成を繰り返さない。
- 補正方式、再同期閾値、先読み時間、許容誤差は最小技術検証の測定で確定する。物理映像と音声の完全同期を仕様として断言しない。
- 音声準備・音声デバイスの待ちで映像を停止しない。準備が間に合わない区間は無音とし、古い位置の音を遅れて出さない。
- 既存の映像補正は維持する。音声側の経路遅延補正が必要かは計測し、追加する場合は映像補正と単位・効果を明示する。

## 6. 形式・資源・障害

- 初期対応音声はAAC・PCM系。MP3などの追加対応は今回の設計変更に混在させない。
- 音声なし／非対応を明示し、映像は継続する。
- 音声ブロック、FFmpeg、復旧準備、ログは有界。音声出力を二重に開かない。
- 音声障害は映像・LTCと分離して通知する。障害復旧で別出力先へ自動変更しない。
- 音声オフからオンにしても映像セッションID、GPUキャンバス、映像復号世代を変更しない。
- 入力・表示系に加えて音声復号を利用するため、従来の「最大2復号」は映像ストリーム数を指すものとする。音声プロセス数とメモリ上限も別途定義・計測する。

## 7. 受入条件

1. 手動再生・LTC同期の両方で音声オン／オフが機能する。
2. 外部映像の開始・停止・失敗・確認取消で音声の位置、デバイス、ストリームを再作成しない。
3. 音声オン／オフ・ミュート・出力先変更・障害で映像時計が巻き戻らず、キャンバスが維持される。
4. 途中オン・シーク・キュー切替・LTC前後ジャンプで古い音を出さない。
5. FREEWHEEL、LOST、ERROR、復帰が状態表に従い、旧世代のバッファが残らない。
6. 蓋画・フェードが音声へ作用しない。
7. 起動時オフ、出力先の明示、切断時に別デバイスへ自動転送しないことを確認する。
8. AAC／PCM、音声なし、非対応、開始時刻差、音量／ミュート、音声オフ時の解放を検証する。
9. バッファ量・ドリフト・再同期回数・使用資源を記録し、短時間試験と耐久・物理遅延測定を分けて報告する。
