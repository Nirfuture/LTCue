# 最終工程前・第2段階：並べ替えと描画障害の扱い

2026-11-11

## 変更した動作

- キューの表示順だけを変更した場合、手動再生・LTC同期・音声を再起動しない。
- 再生内容の変更通知は、LTC形式と検証済みの有効キュー定義を比較して発行する。表示順・再検証だけでは通知しない。開始TCや有効状態を変えた場合は従来どおり反映する。
- 並べ替え時の一覧再構築で遅れて届く選択通知も、素材の再読込につなげない。利用者が別の行を選んだ場合は、その素材を準備する。
- プレビュー単独の描画障害は、既存のプレビュー情報欄に通知する。映像生成・外部映像・音声を止めず、異常が出たプレビューの更新だけを停止する。
- 共通GPUが使えない場合は、プレビューと映像出力に影響することを明示し、映像再生と外部映像を停止する。音声は停止した再生位置に従って無音になる。LTC入力監視は維持する。
- 共通GPU障害が継続するセッションでは同期再生を自動再起動せず、再生・出力開始を無効にしてアプリ再起動を案内する。
- 自動でGPUやプレビューを作り直す復旧処理、新しい操作ボタン、警告による可変高さの領域は追加していない。

## 実装の要点

ShowEditorの表示更新通知とPlaybackChangedを分離した。定義比較では表示順を除外し、無効／有効への遷移も判定する。

MainWindowの並べ替え処理では、コレクション更新中と遅延した選択通知による再読込を防ぐ。既存のキューハンドル・元位置の青線・1クリックの有効チェックは維持する。

RenderSessionはプレビューの失敗を記録し、GetDeviceRemovedReasonとデバイス喪失を示すエラーコードで共通GPU障害を判定する。外部出力や蓋画操作で検出した異常にも同じ境界を適用する。通常成功時には、エラー判定のためのGPU待機・CPU読戻しを追加しない。

主な変更：ShowEditor.cs、MainWindow.CueDrag.cs、MainWindow.axaml.cs、MainWindow.Delivery.cs、MainWindow.Presentation.cs、MainWindow.RenderingHealth.cs、PreviewHost.cs、Playback/RenderSession.cs、native/phase5/Canvas.inc。
