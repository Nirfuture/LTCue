# LTC同期メディアプレイヤー 要件定義書

**Version 0.4 — 2026年11月9日**

## 1. プロジェクト概要

### 1.1 目的

Windows 11上で、外部LTCタイムコードに従い複数の動画を再生し、指定ディスプレイへ映像を送出するメディアプレイヤーを開発する。

動画ファイルを上演キューとして登録し、開始タイムコードに基づく自動切り替えを実現する。

### 1.2 基本方針

- LTCを本番再生の唯一の時刻基準とする。
- デコード、キュー選択、フレーム選択、描画を分離する。
- キューの表示順は再生順に影響させない。
- フレーム精度と長時間安定性を優先する。
- 個別テスト再生は本番同期処理から分離する。
- 物理的な出力同期精度は実測によって評価する。

## 2. 機能要件

### 2.1 映像・同期・出力

| ID | 機能 | 要件 |
|---|---|---|
| F01 | 動画読み込み | MP4/H.264、MOV/HAP、MOV/HAP Qに対応 |
| F02 | LTC入力 | オーディオ入力デバイスを選択してLTCを受信 |
| F03 | LTCデコード | 24、25、29.97 DF/NDF、30fpsに対応 |
| F04 | 同期再生 | LTC時刻から表示対象フレームを決定 |
| F05 | 出力先選択 | 任意の接続ディスプレイを指定 |
| F06 | 全画面出力 | UIのないフルスクリーン表示 |
| F07 | 状態監視 | LTC、映像時刻、現在キュー、同期状態、警告を表示 |
| F08 | 同期オフセット | フレーム単位の表示タイミング補正 |
| F09 | 本番再生制御 | ARM、停止、同期再開 |
| F10 | 同期復帰 | LTC喪失、復帰、時刻ジャンプに対応 |


### 2.1.1 F02 — Audio Input詳細仕様

- Windowsが認識する音声入力デバイスを一覧表示
- 使用するAudio Inputをドロップダウンから選択
- ステレオ入力の場合はL / Rチャンネルを選択可能
- LTC信号の受信状態と入力レベルを表示
- デバイスの切断・再接続を検出
- 選択したデバイスとチャンネルを設定に保存

USBオーディオインターフェース経由のLTC入力にも対応する。

プレビュー音声の出力先（Audio Output）選択は、現時点では必須要件に含まれない。

### 2.2 上演プログラム

| ID | 機能 | 要件 |
|---|---|---|
| F15 | ファイル登録 | D&Dおよびファイル選択 |
| F16 | 開始TC指定 | HH/MM/SS/FFの個別テキスト入力 |
| F17 | キュー管理 | 追加、削除、複製、D&D並べ替え、有効・無効 |
| F18 | 保存・読込 | 上演プログラムのJSON保存・復元 |
| F19 | 自動切り替え | LTC開始時刻に基づく後発優先・上書き切り替え |
| F20 | プリロード | LTC上で次に開始する動画を事前デコード |
| F21 | HAP処理 | HAP/HAP Qの復号・GPU描画への対応 |

F01は対応ファイル形式全体を定義し、F21はHAP固有の処理を定義する。

### 2.3 プレビュー機能（新規）

| ID | 機能 | 要件 |
|---|---|---|
| F25 | 個別テスト再生 | キューを選択し、LTCと独立してプレビュー |
| F26 | プレビュー音声 | 動画に含まれる対応音声をローカル再生 |

プレビューでは再生・一時停止・停止・シーク・音量調整に対応する。

プレビュー音声は、初期版ではAACおよびPCMを対象とする。

プレビューは操作UI内の専用領域に表示し、送出先ディスプレイには影響させない。本番ARM中はプレビューの再生を禁止する。

## 3. 上演キュー仕様

### 3.1 キューデータ

各キューには以下の情報を保持する。

- CueID：一意の識別子
- FilePath：メディアファイルのパス
- StartTimecode：再生開始時刻
- Duration：動画の再生時間
- FrameRate：動画フレームレート
- Codec：動画コーデック
- Enabled：有効・無効
- DisplayOrder：UI上の表示順

Duration、FrameRate、Codecはメディアファイルから取得する。保存済みメタデータについては、読み込み時に実ファイルとの整合性を検証する。

### 3.2 編集操作

- 動画のD&D追加
- キューの追加・削除・複製
- ドラッグハンドルによる並べ替え
- 開始TCの直接編集
- キュー単位の有効・無効切り替え
- キュー単位のプレビュー操作

上下移動ボタンは設置しない。

複製キューは設定を引き継ぐが、初期状態では無効とする。

### 3.3 表示順と再生順の分離

**表示順は再生制御に一切影響しない。**

実際の再生対象およびプリロード対象は、開始TCに基づいて決定する。

## 4. キュー再生制御

### 4.1 後発優先

次のキューの開始時刻に到達した時点で、前の動画が再生中でも新しい動画へ切り替える。

同一開始TCを持つ有効キューが複数存在する場合は競合エラーとし、ARMを禁止する。

### 4.2 LTCジャンプ時の処理

現在時刻以前に開始した有効キューのうち、開始TCが最も新しいものを選択する。

そのキューの再生時間内なら映像を表示し、終了後なら黒画面を出力する。

後発キューが終了しても、先発キューの残りには戻らない。

### 4.3 再生区間の重複警告

開始時刻と動画長から、有効キュー間の重複区間を自動検出する。

- 重複は許可する。
- 重複キューには小さな警告アイコンを表示する。
- ホバー時に重複内容を表示する。
- 編集時に警告を自動更新する。
- 重複だけではARMを禁止しない。

### 4.4 プリロード

- 現在のLTC時刻を基準に次に開始するキューを特定する。
- 動画の切り替え前にファイルを開き、先頭フレームを準備する。
- 表示順はプリロード対象の決定に利用しない。
- LTCジャンプ時には必要に応じて読み込み対象を更新する。
- 準備が間に合わない場合は現在フレームを保持し、エラーを記録する。

## 5. LTC同期仕様

### 5.1 再生位置

LTC時刻、キュー開始TC、同期オフセットから動画再生位置を算出する。

異なるフレームレート間では実時間に変換し、動画のタイムスタンプから表示フレームを決定する。

29.97 DF/NDFの時刻変換は正しく扱う。

### 5.2 同期状態

| 状態 | 動作 |
|---|---|
| WAITING | LTC入力待機、黒画面 |
| LOCKED | LTCに追従して再生 |
| FREEWHEEL | 一時的なLTC喪失を内部クロックで補間 |
| LOST | 長時間喪失時に最終フレーム保持 |
| RESYNC | LTC復帰時に再生位置を再計算 |
| ERROR | 異常を表示・記録 |

FREEWHEEL継続時間、再同期閾値は設定可能とする。初期値は実機検証で確定する。

### 5.3 同期・描画処理

- 非同期デコードと先読みバッファを利用する。
- 表示時刻に対応するフレームを選択する。
- デコード遅延があっても再生時刻を累積的に遅らせない。
- フレーム欠落と重複表示を記録する。
- LTCの大幅なジャンプ時は必要なフレームを再取得する。

## 6. 映像・音声処理

### 6.1 映像デコード

H.264、HAP、HAP Qの復号処理を共通インターフェースから扱う。

HAPについてはGPU圧縮テクスチャへの転送、HAP Qの色変換、ストレージ帯域を考慮する。

### 6.2 本番映像出力

- ユーザー指定ディスプレイへ全画面出力
- VSyncを利用したフレーム提示
- 出力遅延のオフセット設定
- フレーム提示状況の監視

### 6.3 個別プレビュー

- LTC入力を必要としない独立再生
- 再生、一時停止、停止、シーク
- 音量調整とミュート
- UI内プレビュー表示
- 本番出力の描画状態を変更しない

### 6.4 音声出力

v0.4で対応する音声は**プレビュー再生のみ**とする。

本番出力時には動画ファイル内の音声を再生しない。将来の本番音声対応に備え、音声デコード部を映像デコード部と分離する。

## 7. 技術構成

| 領域 | 採用候補 |
|---|---|
| OS | Windows 11 |
| 言語 | C# / .NET |
| UI | WPF |
| 音声入出力 | WASAPI / NAudio |
| LTCデコード | libltc |
| 映像・音声デコード | FFmpeg |
| HAP処理 | FFmpeg / HAP関連ライブラリ |
| 映像描画 | Direct3D 11 |
| 出力制御 | DXGI |
| 設定保存 | JSON |

本番出力とプレビューは独立した再生状態を持つ。ただし、共有可能なデコード・描画基盤は共通化する。

## 8. 非機能要件

| 項目 | 要件 |
|---|---|
| 基準解像度 | 1920×1080 |
| 対応動画FPS | 24 / 25 / 29.97 / 30 / 60 |
| 同期精度 | フレーム単位の追従を目標とする |
| 長時間稼働 | 2時間以上の連続試験 |
| ドリフト | 累積的な再生位置のずれを防止 |
| 安定性 | LTC喪失、復帰、ジャンプに対応 |
| 監視 | 同期状態、フレーム欠落、エラーを記録 |
| プレビュー | 本番送出への干渉を防止 |
| ファイル検証 | 非対応形式、欠損ファイルなどを検出 |

## 9. 開発フェーズ

**Phase 1 — 再生基盤**

MP4/H.264再生、D3D11描画、ディスプレイ選択。

**Phase 2 — LTC同期**

LTC受信、再生クロック、フレーム選択、同期オフセット。

**Phase 3 — 上演キュー**

D&D登録、キュー編集、後発優先、重複警告、JSON保存、プリロード。

**Phase 4 — HAP対応**

HAP/HAP Qの復号、GPU描画、高負荷再生試験。

**Phase 5 — 個別プレビュー**

UI内プレビュー、再生制御、音声出力、本番モードとの分離。

**Phase 6 — 安定化**

LTC異常系、キュー切り替え、同期誤差測定、長時間動作試験。

## 10. 受入条件

### ファイル・映像

- MP4/H.264、MOV/HAP、MOV/HAP Qを読み込める。
- 指定ディスプレイへ全画面出力できる。
- 非対応ファイルを検出できる。

### 上演プログラム

- 複数動画をD&Dで登録できる。
- キューの追加・削除・複製・並べ替え・無効化ができる。
- 表示順の変更が再生順に影響しない。
- 開始TCをHH/MM/SS/FF単位で指定できる。
- JSON保存・読み込みができる。
- 後発優先で動画が切り替わる。
- 重複警告が表示される。
- 同一開始TCの競合を検出できる。

### LTC同期

- LTCに対応するキューと映像位置を選択できる。
- LTC喪失、復帰、ジャンプに対応する。
- 累積的な再生ドリフトが発生しない。
- 同期誤差とフレーム欠落を測定できる。

### プレビュー

- 選択キューをLTCなしで再生できる。
- シーク・一時停止・停止ができる。
- 対応する動画内音声を再生できる。
- プレビュー操作が本番出力に干渉しない。

### 安定性

- 2時間以上の連続動作試験を通過する。
- 高負荷時や異常時の挙動を検証できる。

フレーム単位の同期精度は、内部的なフレーム選択精度と実際の映像表示タイミングを分けて検証する。許容誤差の具体値は実測に基づいて確定する。

**今回の実装対象**

F01〜F10、F15〜F21、F25、F26

**実装対象外**

F11〜F14、F22〜F24、F27

**v0.4の基本方針**

LTC同期映像送出を中核とし、上演プログラム編集と独立した個別プレビュー機能を備える。本番音声出力など同期品質への影響が大きい機能は、初期実装から分離する。
