# LTC Player 音声出力の実装計画 v0.6

2026-11-10 / 対応: LTC_Player_Audio_Requirements_v0.6.md

音声を共通再生へ接続する方針を採用する。現行バイナリはまだ確認用音声の構成であり、本計画の実装完了を意味しない。

## 1. 既存計画への組込み

完了済みの共通GPUキャンバス・映像出力分離は維持する。既存計画の詳細UI確定より先に、下記A〜Cの音声基盤と再生契約を成立させる。音声オン／オフを除去するだけの部分変更は行わない。

音声を含む契約が固まった後にPlaybackCoordinator抽出・設定整理へ進み、その状態モデルを使ってプレビュー・シーク・音声・蓋画UIを確定する。

## 2. 再利用と変更箇所

| 対象 | 方針 |
|---|---|
| MasterClock、CueScheduler | 再利用。音声が同じプレイヘッド・キュー・世代を参照 |
| 共通GPUキャンバス・外部映像Attach/Detach | 維持。音声資源を所有させない |
| PreviewAudioのFFmpeg→PCM・WASAPI出力 | 再利用。ただしPTS情報と同期制御を追加 |
| native/phase5/PreviewAudio.cpp | 出力先指定、実消費位置の観測、停止・Resetによる旧バッファ破棄を追加 |
| PreviewPlayerの音声時計依存 | 共通プレイヘッドへ移す。音声有無で映像時計が変わらない構成へ |
| ArmAsyncのSuppressAudioAsync | 新音声基盤の検証後に撤去。映像出力操作から音声操作を外す |
| LTC優先切替時の音声解放 | 共通音声の同世代切替／再同期へ置換 |
| 設定・UI・テスト | 出力先・音量を保存、オン状態は起動時オフ。新しい状態表を検証 |

## 3. 段階A: 時計・遅延・出力先の最小検証

小さい音声検証用ハーネスを用意し、まだ製品の動作を切り替えない。

- 出力デバイスを列挙・指定し、実デバイスIDを記録する。
- 選択WASAPIストリームを同一所有スレッドで開閉する。
- PCMブロックのPTS、投入量、消費量、実デバイス時計と共通時計の対応を取得する。
- 手動再生と模擬LTCで連続再生・小さいドリフト・前後ジャンプ・LOST・復帰を測る。
- 途中オン、オフ、ミュート、Reset、出力先切断を試す。
- 遅延の基準と、微調整／再シークの方式・閾値を比較して確定する。

完了条件: 旧世代データの遮断、時計の連続性、単一ストリーム、有界バッファを検証し、同期方針の測定根拠を保存する。ドリフト補正を実装したつもりで固定値だけを設定して完了扱いにしない。

## 4. 段階B: 共通プレイヘッドと音声Sink

- 共通の再生モード・キュー・位置・世代を不変スナップショットとして発行する。
- AudioOutputServiceが音声On/Off、選択デバイス、音量／ミュートと状態を所有する。
- AudioDecodeSessionが対応音声の解析、開始PTS正規化、有界ブロック、キャンセルと復旧を所有する。
- 音声消費時計を映像の基準にする現行処理を、音声の追従・補正へ移す。
- 準備後の採用直前に世代・位置を再検査し、古いキューや古い復旧結果を捨てる。
- 音声障害だけで映像・入力・出力を停止しない。

完了条件: 音声オン／オフで映像位置・キャンバス・LTC入力が維持され、手動とLTCの両方で音声が現在位置へ追従する。

## 5. 段階C: 外部映像と音声の独立化

- Arm/Disarmから音声停止・自動ミュート・再開処理を取り除く。
- 出力停止確認中も音声を継続する。
- 蓋画中・映像出力なしでも、音声オンなら共通再生へ追従する。
- アプリ終了だけはすべての出力・入力を終了し、旧FFmpeg・WASAPIを残さない。
- 初期オフと出力先固定を実装し、切断後は明示操作で再開する。

完了条件: 映像On/Off×音声On/Off×手動/LTCの8組合せを検証。双方の操作・障害がもう一方の時計や資源を再作成しない。

## 6. 段階D: UI・設定・回帰

- 音声操作を「プレビュー専用」から「音声出力」へ変更し、外部映像出力中も操作できるようにする。
- On/Off、Mute、無音素材、LOST、準備中、エラーを区別する。
- プレビュー直下シーク、進捗固定領域、フェード秒数の既存UI計画と一緒に配置を確定する。
- 旧設定には保存値がなくても音声オフで起動し、音声形式・JSON・映像設定の互換を維持する。
- 「外部出力開始で音声が止まる」旧試験を「音声ストリームが維持される」試験へ置換する。
- 音声オフでの解放、ミュート解除の現在位置、出力先消失、終了競合を追加する。

## 7. 段階E: 耐久・同期品質

同一素材・同一機器で、連続LTC、頻繁なジャンプ、低速復号、負荷回復、2時間以上の連続稼働を確認する。
共通時計との差、映像PTSとの差、音声消費位置、音声バッファ、復旧回数、CPU／メモリ、プロセス残留を記録する。
機器の出音と物理画面の遅延は内部PTSとは別に測定する。許容誤差・補正値は測定条件と一緒に報告する。

## 8. 報告と現状

各段階で設計判断・実装・試験結果・未解決点を報告する。既存の映像回帰を維持し、音声待ちで映像を止める回避策や、実行時の二重スケジューラーへ置き換えない。
