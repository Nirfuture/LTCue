# LTC Player 音声再生接続の実装・検証記録

2026-11-10 / 音声計画 v0.6 段階B、および段階Cの接続検証

## 実装

- `AudioPlayhead`：再生元がセッション・キュー・世代・位置・単調時計時刻を発行。音声側に別のキュースケジューラーは作らない。
- `AudioDecodeSession`：実素材をFFmpegで48kHz stereo floatへ復号し、実際のフィルター出力PTSを付けたPCMブロックを最大8個保持。準備・出力待ちをキャンセルしてプロセスを終了する。
- `AudioOutputService`：専用スレッドがWASAPIを所有。現在位置へ追従し、音声のON/OFF・ミュート・小さい速度補正・再同期・エラー状態を管理する。ハードウェアへの投入目標は30ms、復号は最大1本。
- 映像開始時刻を基準に音声PTSを正規化する。遅れて始まる音声には先頭無音を残し、先行する音声は映像開始まで切り落とす。非ゼロのコンテナ開始時刻にも対応する。
- 新経路では手動映像を単調時計で進め、音声消費量は追従の観測値として使う。音声OFF・ミュート・映像出力切替で映像時計を変更しない。
- LTC観測から選択キューと目標位置を取得し、採用直前にも世代を照合する。LOST・ERROR・古い通知では音声を停止し、旧データを破棄する。
- 音声エラーは音声サービス内に保持し、明示的な再設定で再試行する。

## 検証中に修正した点

- `-copyts`と入力シークの組合せで、コンテナ開始時刻を二重に加算する扱いになり、開始時刻をずらしたAACが無音になった。入力シークをコンテナ開始からの相対位置へ修正し、元素材と波形比較して検証した。初回の失敗記録も保存している。
- 接続試験の初回では、旧音声用のカウンターが新しい共有WASAPIも数えるため、LTC切替の判定が誤って失敗した。旧手動音声の所有状態そのものを確認する試験へ修正し、再実行で全項目通過した。

PTSとシークの意味は[FFmpeg本体の文書](https://www.ffmpeg.org/ffmpeg.html)、正規化・リサンプリングは[FFmpegフィルター文書](https://www.ffmpeg.org/ffmpeg-filters.html)を参照した。

## 現状と次工程

新経路は内部の明示的な有効化と検証から接続済み。通常UIはまだ旧経路のため、製品としての音声切替は完了扱いにしない。開いている製品アプリを終了・上書きしていない。

次は段階C/Dとして、起動時の旧音声経路無効化、Arm/Disarmに残る旧音声抑制の撤去、音声ON/OFF・出力先・音量のUIと保存設定をまとめて切り替える。その後にプレビュー直下のシーク、進捗による表示領域の伸縮解消、蓋絵フェード秒数のUIを整える。

実機の出力先切断、停止確認中の継続、終了競合、長時間稼働、実LTC入力、物理的な映像と出音の遅延測定は未完了。今回の内部PTS追従を物理的なAV同期精度とはみなさない。
