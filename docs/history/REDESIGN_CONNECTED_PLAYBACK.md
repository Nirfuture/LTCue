# 共通キャンバス接続・出力分離の実装記録

2026-11-10。再設計計画の段階3〜4に対応する実装。

## 実装した動作

- PreviewHostがRenderSessionを常設で所有。手動とLTCの再生ソースは排他的に同じ本番寸法のGPUキャンバスへ描画する。
- 出力ボタンは同一キャンバスへの外部表示先の追加・解除のみ。出力切替でLTC入力、同期タスク、復号、プレビューHWNDを作り直さない。
- 手動再生、LTC、蓋画合成を縮小プレビューと外部表示が共有する。プレビューは幅・高さ各1/2以下、最大30fps。
- LTC優先、FREEWHEEL、LOST保持、受信復帰、手動切替を維持。
- 確認音声を停止する際、再生位置を単調時計へ連続して移し、映像の復号を再起動しない。出力停止で音声を自動再開しない。
- 手動停止・終端は最終映像を保持。停止後の再生は先頭から。一時停止は現在位置から再開。
- 新しい読込・シーク要求は旧準備をキャンセル。準備中は旧映像を保持し、成功後にだけ新フレームを採用する。
- 出力開始失敗でもプレビューを保持し、編集ロックを解除。共通再生エラーと外部表示エラーは外部表示先を解除して通知する。
- 出力ログは上限32件のキュー経由で別タスクに書込み、出力停止時の待機上限は250ms。既存の記録量上限を維持する。
- 入力機器未選択はWAITINGとして手動確認を許可。実際の入力障害はERRORとして区別する。

今回の回帰では、出力切替直後の表示方式が旧観測値のまま残る問題と、速くなった出力開始で連続操作が停止確認へ進む問題を修正した。
出力準備状態を非同期境界として公開し、開始中の追加要求を受け付けない。

実画面で行再生、外部出力開始、停止確認、停止後の最終映像保持を確認した。
外部出力試験は小さい検証用ウィンドウ。標準Flip全画面の既知の危険条件は再実行していない。

## 意図的に変更した既存試験

- 「停止で位置0・黒」を「最終映像保持」に変更。
- 「読込失敗で前の素材を消す」を「最後の有効素材を保持」に変更。
- 「出力停止後の手動状態を破棄」を「保持状態を継続」に変更。
- 素材再解析失敗による出力開始試験は、出力側の作成失敗注入へ変更。出力開始で再解析しない新しい責務に合わせる。
- 本番Rendererの観測フックを使う検証を、実際の共通RenderSessionの状態・読戻しへ変更。

## 現時点の構成と次段階

映像生成先と外部出力の寿命分離は成立した。再生ソースの所有権管理はMainWindowの同期ゲートとPreviewPlayerに残っている。
Coreプロジェクト化、PlaybackCoordinatorの抽出、設定トランザクション、一括キュー検証は後続の構造整理で実施する。
進捗表示・出力状態による画面配置の変動はまだ残る。UI段階で映像矩形を固定し、シーク直下配置とフェード秒数入力を詰める。
新しいUI設計前に、これらを解消済みとは扱わない。

未実施: 長時間稼働、他の環境、全DPI、ディスプレイ抜き差し、物理同期精度、全旧検証群の一括実行。
通常版はartifacts/win-x64へビルドする。リポジトリ指定SDK10.0.403は未導入のため、開発確認は利用可能なSDK10.0.203を使用。
