# 外部出力の提示制御・表示改善の検証記録

確認期間：2026-11-15〜16。記録整理：2026-11-19。

実入力での確認は[実LTC試験記録](2026-11-15_001_PHYSICAL_LTC_TEST.md)を参照。本書は修正候補の診断・実装検証を扱う。

## 外部出力の提示制御

60fpsの実素材で、製品の再生管理・UI・音声処理を通し、ディスプレイ2（cocopar 133OLED）へ1920×1080・標準・全画面出力して測定した。入力時計は検証プログラム内の合成29.97 DFであり、iPhoneからの実入力ではない。各条件の定常区間は約4.5秒。

元の処理は外部出力OFFで約60fps、ONで約33〜40fpsとなった。動画の同一フレームの再提示だけを省いても、全画面・音声ありでは約34fpsのままだった。保持画像の定期的な外部再提示も抑える条件で約60fpsへ戻り、対応MP4と順序反転でも再現した。小さい検証用出力での改善だけでは不十分だったため、初期候補は撤回して再調査した。

実装では、動画の同一CueId・同一復号フレームの重複提示を省く。外部提示は未完了・バックバッファ準備・遮蔽状態を管理し、保持更新では未完了または再描画要求のある場合のみ再提示する。切断/デバイスエラー確認、蓋絵更新、非表示からの保持画像の再表示は継続する。待機8msとスキップ集計は変更しない。

この処理を有効にした全画面・音声ありの短時間測定で、HAP/MP4とも約60fps・スキップ増分0を確認した。数値はアプリが異なるフレームを提示した頻度であり、物理ディスプレイの表示fpsの実測ではない。

描画改善を含む作業版で関連8スイート78項目、CPUジャンプ回復10項目が合格。保持画像のWM_PAINT・非表示復帰を標準/互換の両方式で確認した。通常版・検証版ビルドも成功。これらは作業版の検証結果であり、各コミットを独立して再試験した結果ではない。

## 残る性能問題と未確認事項

同じ全画面・音声あり条件で、60fpsのフォニィMP4/HAPを使用し、0.8秒ごとに8回蓋絵をON/OFFした。蓋絵は診断用64×64の赤画像。

- 切替なし：約60fps、スキップ増分0。
- フェードなしの連続切替：約58〜60fps。
- 1秒フェードを連続反転：約28〜29fps、約6.4秒で約200枚のスキップ。
- 切替終了後：約59〜60fpsへ回復。音声状態はPlayingだが、聴感・物理AV同期の確認ではない。

フェード連打時の性能低下は未解決。修正版の一連の実LTC再確認、全尺再生、2時間耐久、全fps×全形式の網羅確認、物理AV遅延の定量測定は未実施。機能テストの合格を、この性能条件の合格とは扱わない。

## 同期中の進捗・fps表示

同期中もシークバーを提示フレーム位置へ追従させ、操作は禁止したままとする。映像状態は「映像：遅延なし (59.9 fps)」の形式で、数字・括弧・単位は半角。音声表示は維持し、累計スキップ数のツールチップは撤去する。スキップ集計と診断ログは維持する。

fpsはアプリ側の異なる映像フレームの提示回数を1秒ごとに採取し、直近約2秒の平均を表示。素材fpsの90%未満が2秒継続すると数値だけ赤くし、回復で通常色に戻す。開始時は計測待ち表示、入力待ちや停止等では数値を残さない。

関連のタイミング表示テストは11項目合格、通常版・検証版ビルド成功。これは作業版での結果であり、修正後の一連の実LTC受入が完了したことは意味しない。
