# LTC Player 操作UI変更仕様 v0.1

作成日: 2026-11-09 JST

対象: Phase 5完了後のAvalonia版。Phase 6開始前の変更。

本書はユーザーが指定した変更内容を、実装・検証できる形に整理した仕様書である。文書作成時点では本変更を実装していない。元の要件v0.4と開発指示書は保存し、本書に記載した項目だけを差分として置き換える。記載のない同期・キュー選択・コーデック・JSON仕様は維持する。

## 1. 基本方針

**映像表示領域は1つだけとする。停止中は選択キューの確認に使い、配信を開始すると本番送出映像のモニターに自動で切り替える。**

ユーザーにMain/Cueの画面切替や2つの再生系の同時操作を求めない。モード切替タブ、2画面表示、配信中の別キュープレビューは設けない。

本書の「配信」は指定ディスプレイへのLTC同期映像送出を意味する。ネットワーク配信・エンコード・配信サービス連携は追加しない。

## 2. 画面構成

- 上部: 常時表示のLTC、受信状態、配信/配信停止の1ボタン、設定ボタン。
- 主領域: キュー一覧と、1つの映像表示領域。
- 映像領域の周辺: モード、対象キュー名、位置/長さ、必要な操作部。
- 警告/エラー: 状態欄に表示。色だけに依存しない。

画面内の「LTC PLAYER」「SHOW CONTROL／独立プレビュー」は削除する。OSタイトルバーのアプリ名はウィンドウ識別用として残す。

固定の「CUE PREVIEW」「MAIN PREVIEW」という見出しは使わない。停止中は「プレビュー」、送出中は「配信中」、準備中は「配信準備中」と表示する。

## 3. 統一プレビュー

### 3.1 配信停止中

- キューを選択すると先頭フレームを表示する。選択だけで音声再生を開始しない。
- 各キュー行の再生操作で、そのキューを選択してプレビュー再生する。同時再生は1本まで。
- 他のキューを再生した場合、前のプレビューの映像・音声処理を停止して切り替える。
- 再生中の行は「一時停止」、一時停止中は「再開」と分かる表示にする。停止は当該キューのプレビューを位置0・黒画面へ戻す。
- 別の行の停止操作で、再生中のキューを誤って停止しない。停止できるのは現在プレビューに読み込まれている行だけとし、それ以外の停止操作は無効とする。
- シーク、音量、ミュートは映像領域に付属する共通操作として残す。再生・一時停止・停止ボタンは各行へ集約し、同じ操作を映像領域側に重複配置しない。
- AAC/PCM音声をWindows既定出力で再生する現行仕様を維持する。未対応音声・音声なしの表示も維持する。

### 3.2 配信中

- 同じ映像領域を本番映像モニターとして使用する。ユーザーによるモード選択は不要。
- 表示するのは本番描画で実際に採用・提示された映像。選択行やLTCから別途計算した再生結果を表示しない。
- キューのない区間は黒、本番がフレーム保持している間は同じ映像を保持する。現在キュー、映像PTS、同期状態も対応する本番観測値を表示する。
- キュー行のプレビュー再生/一時停止/停止は無効。配信中に行を操作しても別キューのプレビューへ切り替えない。
- シーク・音量・ミュートは非表示とする。位置表示を残す場合は読取専用にし、操作できるシークバーに見せない。
- プレビュー音声は再生しない。本番動画の音声出力も追加しない。
- この表示は送出内容のモニターであり、接続ディスプレイの光学的な表示タイミングを測定するものではない。

### 3.3 シーク位置の更新

- 再生中のつまみは、マウスがバーに乗っているだけでも継続して進む。
- ユーザーがつまみ/バーを押して位置指定している間だけ、自動追従を一時停止する。
- ボタンを離した位置でシークし、その後は実際の再生位置に追従する。
- キーボード操作中も操作と位置更新の競合を防ぎ、操作終了後は追従を再開する。単なるキーボードフォーカス保持を追従停止条件にしない。
- 配信開始、停止、キュー変更、フォーカス/ポインター捕捉喪失で未確定シークを破棄する。古い操作が配信モードに届かないようにする。

## 4. LTCの常時監視

- アプリ起動後、保存済みの入力デバイス・L/R・LTCモードで受信処理を開始する。配信ボタンとは独立させる。
- 初期未受信は「--:--:--:--」。受信中は最新の実受信TCを表示する。
- 喪失時は最終受信TCを薄く表示して受信喪失を明示する。FREEWHEEL等の同期状態を併記し、未受信値を実受信したように表示しない。
- 配信開始/停止、停止確認ダイアログ、設定モーダル表示中も監視・表示を継続する。
- 受信サービスとMasterClockはアプリ単位で1組。配信開始時に同じデバイスを二重に開かず、監視中のクロックを本番送出が参照する。
- 入力変更時は旧受信処理を停止・解放してから新しい入力を開く。別入力/別モードの古いTC・世代・日跨ぎ状態を引き継がず、WAITINGから受信し直す。
- 入力機器が未接続でも起動を妨げない。既存の再接続処理を活かし、選択IDを保持して状態を表示する。
- JSON読込でLTCモードが変わる場合も、この設定変更経路を通して監視と上演設定の不一致を防ぐ。

## 5. 配信ボタンと状態遷移

| 状態 | ボタン | 映像領域 | キュー編集/個別再生 |
|---|---|---|---|
| 停止中 | 配信 | キュープレビュー | 可 |
| 開始準備中 | 配信準備中（連打不可） | 黒/準備表示 | 不可 |
| 配信中 | 配信停止（赤） | 本番映像 | 不可 |
| 停止確認中 | 配信停止（赤） | 本番を継続表示 | 不可 |
| 停止処理中 | 停止中（連打不可） | 本番モニターから黒へ | 不可 |

- 赤色に加えて「配信停止」という文字で状態を明示する。
- 開始時にプレビューを停止して音声を解放し、映像領域の所有権を本番モニターへ渡す。旧プレビューから遅れて届いた描画や状態通知は破棄する。
- 開始検証で失敗した場合は配信を開始せず、停止中へ戻してエラーを表示する。プレビュー再生は自動再開しない。
- 停止完了後は選択キューの先頭フレームを再表示する。選択キューがなければ黒。配信前のプレビュー再生位置・音声は自動再開しない。
- 準備中のボタン連打は無視する。アプリ終了要求などで準備をキャンセルした場合、後から本番ウィンドウが現れないこと。

### 5.1 停止確認

- 配信ボタン、Esc、本番出力ウィンドウを閉じる操作からの停止要求は、共通の確認処理へ集約する。
- 文言は「配信を停止しますか？」。選択肢は「配信を続ける」「配信を停止」。既定フォーカスは「配信を続ける」。
- ダイアログのEsc/閉じるは取消として扱う。ダイアログは多重に開かない。
- 確認中はLTC監視、本番描画、本番モニターを継続する。取消時は配信状態を一切リセットしない。
- 配信中のアプリ終了は「配信を停止して終了しますか？」とし、承認時だけ送出・監視を終了する。停止確認を二重に出さない。
- 機器障害・描画エラーによる自動停止は、確認を待たず安全に終了してエラーを通知する。ユーザー操作の確認処理と分ける。

## 6. 設定モーダル

- 現在の画面内Expanderを撤去し、設定ボタンからオーナー付きモーダルを開く。
- 入力デバイス、L/R、LTCモード、出力ディスプレイ、同期補正、FREEWHEEL、再同期閾値を配置する。
- 編集用コピーを使い、「適用」で検証・保存・反映、「キャンセル」/閉じるで変更を破棄する。入力中の値を即座に実受信へ反映しない。
- 不正値はモーダル内で表示して適用を禁止する。適用失敗時は前の有効設定を維持するか、受信不能を明示してWAITING/ERRORとする。新旧混在状態を残さない。
- 配信中は閲覧専用。「配信中は設定を変更できません」と表示し、適用不可。モーダルを開いても配信は止めない。
- 受信入力を変える設定適用時は、キュープレビュー再生も停止する。閉じた後に勝手に再生しない。

## 7. 技術上の境界

- 1つの表示領域でも、Cue再生と本番送出の再生状態は共有しない。共用するのは表示先であり、本番の時計・シーク操作ではない。
- 表示領域への書込み権限を状態と世代番号で管理し、Cue/本番/準備/終了処理が競合しないようにする。
- 本番モニターのために別のデコーダーや別のキュースケジューラーを動かさない。
- 本番GPU画像から同一デバイス内で縮小表示する方式を第一選択とする。毎フレームの全画素GPU読戻し→CPU→再転送を通常経路にしない。
- モニターは最大640×360相当・15fpsを初期上限とする。本番の提示を優先し、モニター更新を待たない。待機フレームは最新1枚までとし、モニター側の間引きを本番のフレーム欠落へ混入させない。
- 本番モニターを初期化できない場合は開始失敗として報告し、本番のみを無言で開始しない。配信開始後のモニター単独障害では本番を継続し、領域をエラー表示にする。ユーザーによる停止は確認を通す。

## 8. 既存要件との対応と対象外

| 元の項目 | 今回の差分 |
|---|---|
| GUI WPF | 現行のAvalonia版を対象とする。旧WPF版は保存 |
| F02/F03/F07 | LTC受信を配信から独立させ、停止中も状態表示 |
| F09 | ARMのUI表現を1つの配信ボタンと停止確認へ変更 |
| F25/F26 | 停止中は個別確認、配信中は同一領域で無音の本番モニター |
| ARM中の個別プレビュー禁止 | 維持。禁止するのは別キューのテスト再生で、本番映像のモニター表示は行う |
| F16/F17 | 各キューの再生操作を追加。開始TCと表示順の意味は維持 |

ネットワーク配信、本番音声、複数独立出力、Genlock、配信中のキュー編集/別素材再生、追加コーデックは対象外。

## 9. 受入条件

1. ホバーだけ・フォーカスだけでシーク位置表示が停止しない。ドラッグ/キーボード操作終了後は追従する。
2. 画面内の指定タイトル文字と二重プレビューがなく、状態により1領域が切り替わる。
3. 停止中も5 LTCモードを受信・表示でき、配信開始/停止で入力を開き直さない。
4. 配信停止の取消中も送出・TC・モニターが進み、承認時だけ停止する。Esc/ウィンドウ終了でも確認を迂回しない。
5. 設定の適用/取消と配信中閲覧専用が成立し、モーダル表示中も本番が進む。
6. 行操作は正しいキューだけを再生/停止し、配信中はUIとサービスの両方で拒否される。
7. 配信モニターは黒区間、保持、LTC復帰/ジャンプ、混在コーデック切替で本番と対応する。行選択で切り替わらない。
8. 開始失敗・準備中取消・終了・繰返し切替で、音声や描画リソース、古い通知が残らない。
9. 本番モニターの有無で本番提示間隔/欠落/ホスト負荷を比較し結果を保存する。短時間試験を物理同期精度や長時間安定性の確認とは扱わない。

具体的な試験方法と実装順序は同梱の「LTC_Player_UI_Change_Implementation_v0.1.md」に従う。
